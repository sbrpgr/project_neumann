# Neumann

연구를 시작하기 전에, 비슷한 연구가 실제 심사에서 받은 지적으로 내 연구계획서의 위험을 미리 점검하는 서비스.

## 무엇을 하나

연구계획서를 넣으면

1. 공개 심사 기록 코퍼스에서 **비슷한 연구**를 찾고,
2. 그 연구들이 실제로 받은 **심사평·저자 답변·결정 기록**에서 반복되는 지적을 뽑아,
3. **근거가 연결된 위험카드**로 돌려준다. 카드마다 실제 심사평 문장을 원문 오프셋 그대로 인용하고 원문 링크를 단다.

- 분석 대상은 논문 본문이 아니라 평가 과정 기록이다. 개입 시점은 투고 직전이 아니라 연구 착수 전이다.
- 제품 LLM은 OpenAI API다(기본 모델 `gpt-6.1-sol`). 아래 수치 중 LLM으로 잰 것(Macro-F1 0.4864, 라이브 E2E)은 `gpt-6-astra`로 잰 값이다(평가 모델 gpt-6-astra, 제품 기본 모델 gpt-6.1-sol). 빈도 기준선·사람 상한·코퍼스·색인 수치는 LLM 측정이 아니다. 지금은 astra 모델을 쓰지 않는다(모델명에 astra가 있으면 코드가 sol로 바꾼다). LLM은 인용문을 쓰지 않고 발췌 id만 돌려주며, 인용 문자열은 코드가 원문에서 잘라 붙인다.
- API가 실패하면 그 단계만 비상 규칙 경로로 돌리고, 결과와 화면에 강등과 생성 방식(astra·rule·mock)을 그대로 표시한다.
- 범위는 AI 활용 과학 연구(AI for Science) 계획서다.

## 지금 상태 (v0)

태그 `v0`: 계획서 입력 → 유사 연구 + 위험카드(실제 심사평 인용)가 실데이터·실제 LLM(`gpt-6-astra`)으로 끝까지 돈다.

**목표 미달부터:** 심사평 위험 유형 추출의 DISAPERE 골드(사람 라벨 148건) 리뷰 단위 Macro-F1은 **gpt-6-astra 0.4864 [95% 0.4276, 0.5394]**로, 신청서 목표 0.70에 못 미친다. 같은 골드에서 빈도 기준선(심사평을 읽지 않고 최빈 3개를 내는 것)은 0.3308 [0.2980, 0.3623], 사람끼리의 일치 상한(참조선)은 0.725다. astra가 기준선보다 높은 것은 Macro-F1에서만이고, Micro-F1(astra 0.5644, 기준선 0.5379)은 구간이 겹친다. 추출 지시문은 제품 그대로(조정한 것은 집계 규칙뿐), 골드는 1회 채점, 단일 실행 값이다.

| 항목 | 실측 |
|---|---|
| 코퍼스 | OpenReview 공개 심사 기록(ICLR 2024·2025) 중 AI for Science 논문 1,128편, 심사평 5,366건(공식 심사평 4,298 + 메타리뷰 1,068) |
| 검색 색인 | 심사평 문장 133,769개, 원문 오프셋 전량 대조 100% |
| 라이브 E2E(로컬 실서버, `gpt-6-astra`) | 5/5 통과: 데모 계획서 3건 카드 5·3·5장, 범위 밖 입력 1건 카드 0장과 사유 표시 |
| 근거 연결률 | 데모 3건 모두 1.0(근거 10/10·13/13·20/20, 원문 글자 단위 대조) |
| 분석 시간 | 계획서 1건 약 62~70초(화면에서 분석 버튼 → 리포트) |

| 단계 | 내용 | 태그 |
|---|---|---|
| L0 | 계획서 입력 → 유사 연구 + 위험카드(실제 심사평 인용) | `v0` 달성 |
| L1 | 위험점수, 예상 심사평, 근거 열람 패널 | 진행 중 |
| L2 | 체크리스트·결정 로그, 백테스트(보류), 내보내기 | 진행 중 |
| L3 | 디자인, 규모 확대, 리포트 카드 | 진행 중 |

## 실행

설치·환경변수·데이터 준비·서버·테스트는 [docs/RUNNING.md](docs/RUNNING.md). 요약:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv -r pyproject.toml --extra dev
git config core.hooksPath .githooks
python -m uvicorn neumann.api.main:app --host 127.0.0.1 --port 8000   # 기본 mock
```

기본 provider는 `mock`이다(비용 없음, mock 결과는 분석이 아니며 그렇게 표시된다). 실제 분석은 `NEUMANN_LLM_PROVIDER=openai`와 환경변수 `OPENAI_API_KEY`로 켜며, 그때는 분석 요청마다 OpenAI API를 부르고 비용이 든다.

## 보안

공개 저장소다.

- 비밀값은 환경변수(또는 커밋되지 않는 `.env`)에만 두고 코드는 환경변수로만 읽는다. `.env.example`에는 키 이름만 있다.
- `.gitignore`가 `.env`, 데이터, 모델 가중치, 색인, 캐시, 로그를 막는다. `scripts/verify.py`와 git 훅(`pre-commit`·`commit-msg`·`pre-push`)이 키 형태 문자열, 실제 키 값, 금지 파일, 5MB 넘는 파일을 찾는다. GitHub 시크릿 스캐닝과 푸시 보호가 켜져 있다.
- 서버 응답에는 예외 원문·상류 API 오류 문구·내부 경로를 싣지 않는다.
- 입력 화면에 "계획서는 분석을 위해 OpenAI API로 전송된다, 개인정보·미공개 기밀은 넣지 말 것, 본문은 파일로 저장하지 않는다"는 고지를 띄운다.
- 공개 서버: 접근 토큰 없이 공개할 계획이다. 일일 예산 상한은 걸지 않는다(결정 기록 19:46). 안정성 장치(E4-L2c·E4-L2d, main 병합)로 동시 분석 상한·대기열·IP별 속도 제한·비동기 작업 API(Cloudflare 응답 시간 상한 대응)·입력 크기 상한이 있고, 공개 기동은 `scripts/serve.py --public`으로 한다(행사 권장값은 `.env.example` 주석). 다중 사용자 동시성(SEC-5)과 OpenAI 동시 요청 상한도 들어 있다. 공개 터널은 공개 전 보안 재점검(SEC-2r) 필수 조치 뒤에 연다.

## 개발 방식과 반입 자료

- 2026 NAIS AI 해커톤 본선(2026-09-30 17:00 ~ 10-01 12:00) 현장에서 만들었다. 17:00 이전 커밋은 없고 첫 커밋은 18:06이다. 커밋 이력이 곧 현장 개발 기록이다.
- 사람(대표)과 AI 코딩 에이전트(빌더·검증자 분리)가 과제 단위로 개발했다. 과제 지시문과 보고서·검증 보고서는 `docs/tasks/`·`docs/reports/`에 있다.
- 반입한 것은 주최측이 허용한 기획 자료와 공개 자료뿐이다.
  - 기획 문서와 목업: 화면은 기획 단계 목업을 바탕으로 현장에서 재구성했다(`webui/index.html`의 의미 있는 줄 약 55%가 목업과 같다, 19:22 측정). `contracts/` 스키마는 기획 문서 원본이다.
  - 공개 데이터·모델: ResearchArcade, DISAPERE, Retraction Watch, bge-m3, 폰트, JSZip 원본 그대로. 가공물(코퍼스·색인·라벨·캐시)은 모두 현장에서 만들었다.
- 사전 개발 점검: 개발용 venv에는 라이브러리만 있었고(9/29 설치), 공유 데이터 폴더의 파일은 모두 17:00 이후 현장에서 만들어졌으며, 기획 자료에는 코드가 없다(공개 라이브러리 JSZip만).
