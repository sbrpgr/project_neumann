# [PLAN-FR2] 구현 경로 제시와 제한된 실행 검증 기획

- 개정일: 2026-10-01 (KST)
- 최신 구현 범위: 대표가 요청한 최종 검사·교정은 `FINALIZATION_IMPLEMENTATION.md`를 따른다. 제약·단위·선행 관계의 제한된 실제 도구 검사를 우선 구현하며, 아래의 범용 최소 실험 실행기는 후속이다. 도구 결과를 연구 전체의 물리적 타당성이나 실제 실험 성공으로 확대하지 않는다.
- 근거: 대표의 반영 지시와 "수정확정 했을때 검토 및 검증까지 함께"라는 흐름 통합 지시.
- 상태: **구현 예정**. 이번 작업은 기획 문서 반영이며 제품 코드·계약·실서비스·실제 API 실행은 포함하지 않는다.
- 순서: 수정 권고·계획서 조립·최종 문안 검토의 통합 후 후속 후보로 검토한다. 기존 L3 과제 배정·일정·릴리스 태그를 자동 변경하지 않는다.

## 1. 목적

과거의 심사 지적과 확인된 실패 원인을 현재 계획의 구현 조건으로 바꿔, 구현 방법과 선행 조건, 작은 검증으로 확인할 수 있는 범위를 제시한다. 심사 지적·거절과 실제 연구 실패는 구분하고, 원래 사례와 현재 계획의 맥락 및 적용 이유를 설명한다.

구현 경로 제시와 제한된 실행 검증은 서로 다른 산출이다. 구체적인 제안이 있다고 구현이 확인된 것은 아니며, 코드를 실행했다고 핵심 가정이나 전체 연구의 타당성이 입증된 것도 아니다. 실제 실행의 관측 범위만 보고한다.

## 2. 한 작업의 입력과 출력

입력은 고정된 계획서, 연결된 기존 근거, 연구자가 제공한 자료·코드·환경 명세다. 선택한 핵심 가정은 1개다. 근거가 부족하면 적용 판단을 보류하고 그 이유를 반환한다. 자료를 임의로 존재한다고 가정하지 않는다.

| 출력 | 필요한 내용 |
|---|---|
| 구현 경로 | 계획서 대상 위치·가정, 적용 근거, 구현 단계, 필요한 데이터·코드·도구·환경 |
| 선행 조건 | 제공 자료에서 확인된 준비 항목, 부족하거나 확인이 필요한 항목, 판단 이유 |
| 최소 검증안 | 질문, 비교군(필요한 경우), 측정 지표, 사전 판정 기준, 명령·절차, 실행 한도 |
| 실행 결과 | 실제 수행 명령·버전·자료 식별값·종료 상태·측정값·오류·한계·산출물 식별값 |
| 계획서 반영 제안 | 유지·수정·추가 확인할 주장과 위치, 관측으로 뒷받침되는 범위 |

수치·자원 추정은 연구자가 제공한 제약이나 명시된 측정·추정 근거를 연결한다. 근거 없는 표본 수·성능·비용·시간을 채우지 않는다. 예측값·추정값·실측값을 구분한다.

## 3. 상태는 세 축으로 구분한다

| 축 | 표시할 상태 |
|---|---|
| 구현 제안 | 제안됨 / 근거 부족으로 판단 보류 |
| 준비 상태 | 확인 범위에서 준비됨 / 선행 조건 부족 / 확인 필요 |
| 실행·판정 | 미실행 / 실행 완료 / 실행 실패 / 실행 미완료, 그리고 사전 기준 충족 / 미충족 / 판단 보류 |

실행 완료와 기준 충족은 별개다. 절차는 정상 종료했지만 가정에 불리한 결과가 나올 수 있다. 자료가 없어 실행하지 않은 경우 구현 제안과 필요 자료를 반환하고 실행 축은 미실행으로 남긴다. mock·합성 데이터·코드 초안은 실제 제공 자료의 실행 검증으로 표시하지 않는다. 생성 방식은 기존 제품 표기 규칙을 따른다.

## 4. 사용자 흐름과 실행 경계

1. 수정 화면에서 핵심 가정 1개의 구현 경로·준비 상태·최소 검증 범위를 보여준다. 문안·자료가 바뀌면 사전 범위를 갱신하고 이전 실행 승인을 재사용하지 않는다.
2. 실행 가능한 경우 같은 화면에서 대상 가정·자료·방법·측정/판정 기준·자원 상한과 실행 포함 선택을 제시한다. 도구·명령 규격은 승인 범위에 연결하되 상세에서 확인할 수 있다. 실행 포함을 선택하지 않거나 범위가 승인되지 않으면 실제 실행하지 않는다.
3. 연구자가 `수정 확정·검증`을 누르면 문안·자료·검증 범위·승인을 고정한다. 단일 작업에서 최종 문안 검토와 구현 조건 점검을 수행하며, 준비·승인된 경우 최소 검증 과제 1건을 포함한다. 한 과제의 비교군과 여러 고정 단계는 승인한 절차에 모두 포함한다.
4. 자료·환경이 부족하거나 실행을 포함하지 않은 경우 구현 경로·필요 자료·검증 절차를 반환하고 실행 축은 미실행으로 남긴다. 이 경우에도 완료한 문안 검토를 반환한다. 결과와 화면에 각 내부 단계의 완료/실패/미실행을 구분한다.
5. 계획서·변경 이력·문안 검토·구현 조건·관측 결과·한계·반영 제안을 한 결과로 반환하고 종료한다. 본문을 자동 변경하거나 필수적인 두 번째 확정/별도 검증 요청을 추가하지 않는다. 추가 실험·코드 보완·다른 가정 검증은 연구자의 별도 요청이다.

초기 실행 대상은 데이터·코드가 제공되고 격리 환경에서 수행 가능한 계산 연구다. 후속 구현에서 네트워크·쓰기 범위·실행 도구와 명령·자원 제한을 강제하고 제공 자료의 원본을 수정하지 않는다. 도구 명령은 허용된 실행 규격을 거쳐야 한다. 제한이 구현되지 않은 상태로 생성된 코드를 제품 서버에서 실행하지 않는다.

한 작업은 핵심 가정 1개, 최소 검증 과제 1건으로 고정한다. 자동 재실험·코드 재수정 반복은 0회다. 실패·시간 초과·기준 미충족도 표시 후 종료하고 무한 개선을 시도하지 않는다. 같은 실행 요청의 중복 전송은 기존 작업으로 처리하여 추가 실행을 만들지 않는다. 승인 이후 문안·자료·명령·판정 기준이 바뀌면 기존 승인을 재사용하지 않는다.

문안 최종 검토의 1회·자동 재수정 0회 제한은 그대로다. 단계별 실패·미실행이 있어도 수행된 결과와 한계를 반환하고 전체 검증 성공으로 합치지 않는다. 수정 확정은 문안 고정이며 실행 승인이나 과학적 타당성 확인을 대신하지 않는다. 실행 결과로 연구자가 문안을 변경하면 기존 문안 검토는 이전 문안의 기록으로 남긴다. 실행 결과는 고정된 계획·자료·코드 버전에만 연결한다.

## 5. 예시와 검증 범위

실제 심사에서 데이터 누출이 지적된 사례가 현재 계획에 적용되는 경우, 데이터 분할·표본 중복·전처리 순서를 구현 조건으로 제시한다. 제공된 자료·코드로 해당 검사를 수행하면 결과와 검사하지 못한 범위를 보고한다. 누출 검사의 통과를 성능 향상·일반화·전체 연구 성공의 증거로 확대하지 않는다.

파일 로딩과 작은 입력 실행을 확인한 예비 점검은 실행 준비의 관찰이다. 연구 가정을 검증하는 실험과 구분한다. 필요한 비교군이나 판정 기준이 빠지면 핵심 가정을 확인했다고 쓰지 않는다.

## 6. 후속 구현과 완료 기준

PM은 추가 계약·실행 경계·승인 정책을 정한다. E3는 가정/근거 연결·구현 경로·최소 검증안·결과 대조, E4는 승인·작업 상태·결과 반환, E5는 반례와 효과 평가를 맡는 후속 후보로 둔다. 이번 문서는 작업 배정이나 구현 완료를 뜻하지 않는다. mock/offline 개발과 실제 API 확인 제한은 AGENTS.md를 따른다.

| 필요한 반례 | 완료 기준 |
|---|---|
| 자료·환경 누락 | 부족 항목과 미실행 표시, 구현 확인으로 통과하지 않음 |
| 승인 없음·승인 이후 입력 변조 | 실행하지 않음, 기존 승인 재사용 거절 |
| 다른 맥락의 실패·지적 | 적용 이유 부족을 판단 보류로 표시 |
| 실행 성공·기준 미충족 | 실행 완료와 부정적 판정을 함께 표시 |
| 코드 초안·mock·예비 점검 | 실제 가정 검증으로 잘못 표기하지 않음 |
| 시간 초과·오류·자원 초과 | 실패/미완료와 수행 범위 반환, 자동 재실험 0회 |
| 중복 요청·다른 가정 추가 | 동일 실행 중복 0, 추가 가정은 별도 작업 |
| 원본 자료·최종 문안 보존 | 자동 덮어쓰기 없음, 버전 식별값 연결 |
| 범위를 벗어난 실행 | 승인·도구·네트워크·쓰기·자원 제한이 실제로 차단 |
| 사용자 흐름·부분 완료 | 확정·검증 1회 제출, 자료 부족에도 문안 검토 반환, 내부 단계별 완료/실패/미실행 표시 |

후속 구현은 다른 모델의 독립 검증과 해당 변경의 verify 통과가 필요하다. 위 표는 이번 문서 작업의 제품 테스트 결과가 아니다.

효과는 구현 경로의 구체성, 선행 조건 판정, 재현 가능한 실행 기록, 잘못된 확인 판정의 발생으로 평가한다. 평가 기준은 결과 확인 전에 고정한다. 실제 반려율 감소나 과학적 성과는 별도 추적 전까지 입증됐다고 말하지 않는다.
