# E3-L1s 보고서: 짧지만 분야가 분명한 입력에 카드 0장 — 제품 결함 수정

- 빌더: claude-opus-5.5, 브랜치 `task/E3-L1s`(main `c8ba766`에서 시작)
- 실제 OpenAI 호출 0회. 모든 측정은 mock provider, 가짜 코퍼스, 또는 로컬 실색인(bge-m3, 오프라인)으로 했다. 재실행은 하지 않았다.
- 방침(대표, 작업 중 변경): **너무 짧으면 거절(LLM 호출 0, 무엇을 더 적을지 안내), 짧으면 경고 후 끝까지 분석(카드 0장 금지), 범위 밖은 지금처럼 거절.**

## 1. 무엇을 했나

1. 원인 확정(실행 파일 `data/eval/neumann_runs/real__*.json`): 0장 3편 모두 `fitness=uncertain` + 검색어 단계 `is_research_plan=False`(검색어 [])에서 `pipeline.py`가 추출 전에 멈췄다. 이때 검색 상위 점수는 0.760·0.742·0.808로 높았다. E5-L2d 진단과 같은 결론이고, 그 보고서의 수정안 P1(부록 A)을 출발점으로 삼아 키 이름(`plan_checks.search.queries_source`=`llm|rule`, `plan_checks.suitability.thin_input`)을 맞췄다.
2. 입력 분량 단계(`fitness.input_quality`)를 만들었다. 거절은 호출 없이 끝나고, 경고는 결과와 화면에 표시한다. 옛 MIN_CHARS 사전검사는 거절 단계로 합쳤다.
3. 경고 단계 입력이 끝까지 분석되게 했다. 판정 보류라도 유사 연구 근거가 강하면 진행한다(기준은 실측). 검색 하한 아래면 상위 k편을 쓰고 "낮은 유사도"로 표시한다. 카드가 0장이면 분야 수준 카드(규칙 합성)를 만든다.
4. 화면 데이터(`view.py`)에 `_status.input_quality`·`_status.search`를 추가하고, 경고·거절 문구를 notices 맨 앞과 라벨에 넣었다. `index.html`은 고치지 않았다(기존 공지 상자가 라벨이 있으면 notices를 보여 준다).
5. 검색어 지시문을 v2로 바꿨다. 연구 배경이나 아이디어만 있는 글에도 검색어를 쓰게 했다(연구와 무관한 글만 []).

## 3. 입력 분량 단계 기준(확정)과 기준표

환산 글자 수 = 공백 제외 글자 + 한글 음절마다 1.5자. 한글 1음절을 로마자 2.5자로 본다. 문장·항목 수는 문장 끝 부호 뒤 공백이나 줄바꿈으로 나눈 조각 가운데 낱말 3개 이상 또는 12자 이상인 것만 센다. 요소 수는 연구 질문·방법·데이터·평가의 규칙 표지 수다.

| 단계 | 조건(위에서부터) | 동작 |
|---|---|---|
| 거절 `too_short` | 환산 80자 미만(영어 80자, 한글 약 32음절) | LLM 호출 0. "입력이 너무 짧아 분석하지 않았습니다(…). 연구 질문·방법·데이터·평가를 더 적어 주세요 — 빠진 요소: …" |
| 거절 `demonstrative_sentence` | 문장·항목 1개 이하이고 지시어로 시작("This/It/Such…", "이는/이러한…") | 같음 |
| 거절 `single_sentence` | 문장·항목 1개 이하이고 요소 3개 미만 | 같음 |
| 거절 `no_topic` | 환산 600자 미만이고 분야 표지·방법 표지·무관 표지가 모두 없음 | 같음. 무관 표지가 있는 글은 여기서 거절하지 않고 지금처럼 적합성 판정이 "연구계획서가 아니다"로 거절한다 |
| 경고 `short`·`few_elements` | 환산 600자 미만, 또는 요소 2개 이하 | 끝까지 분석. "입력이 짧아 결과 신뢰도가 낮습니다 — 연구 질문·방법·데이터·평가를 더 적어 주세요(…)" |
| 경고 `fitness_uncertain`·`few_elements_llm` | LLM 적합성이 보류이거나, 근거 줄이 있는 요소가 2개 이하 | 같음(긴 계획서도 해당) |
| 보통 `ok` | 위에 해당 없음 | 경고 없음 |

대표의 처음 제안(거절 = 200자 미만 또는 한 문장 이하)에서 두 가지를 바꿨다.
- 200자를 환산 80자로 낮췄다. 200자 기준이면 한국어 두 문장 계획(예: W01 "그래프 신경망(GNN)으로 … 이온전도도를 예측한다. … MAE로 평가한다.", 공백 제외 62자)과 기존 테스트의 "아이디어 구상 중" 입력(48자, `test_thin_idea_is_uncertain_with_followups`)이 거절된다. 둘 다 "분야·방법을 알 수 있는 입력"이다.
- 한 문장이라도 요소가 3개 이상이면 거절하지 않는다(W02·W17). 지시어로 시작하는 한 문장은 요소 수와 상관없이 거절한다.

## 4. 경고 단계 진행 조건(검색 근거 기준) — 실측

실색인(1,128편, bge-m3 하이브리드, 로컬), 규칙 검색어(검색어 단계가 []일 때 파이프라인이 쓰는 것)로 쟀다. 관련도는 `max(dense, score)`로, E2 하한과 같은 값이다. 백테스트는 자기 논문을 뺐다(누출 제거와 같다).

| 묶음 | 건수 | 상위 관련도 | 관련도 0.50 이상 논문(상위 10편 중) |
|---|---|---|---|
| 범위 밖(N01~N05, negative_recipe, RECIPE) | 7 | 0.349~**0.426** (하한 0.45 통과 0편) | **0** |
| 경고 단계(W01~W21 + 백테스트 U3PB·SFCH·o1Ii) | 24 | **0.541**(W15 산불)~0.873 | **6**~10 |
| 거절 단계(X01~X12, ihHe) | 13 | 0.49~0.81 | 0~10 → 검색 점수로는 얇은 입력을 가를 수 없다. 그래서 분량 단계가 필요하다 |

그래서 진행 조건을 **상위 관련도 0.50 이상, 관련도 0.50 이상 논문 3편 이상**으로 정했다(`pipeline.RESEARCH_GATE_MIN_TOP`, `RESEARCH_GATE_MIN_WORKS`). 범위 밖 최대 0.426과 경고 최소 0.541 사이에 양쪽 여유가 있고, 편수 조건은 한 편만 우연히 맞는 경우를 막는다. 이 기준은 bge-m3 척도에서 잰 값이다. 가짜 코퍼스(토큰 코사인)에서는 0.50 이상이 1편뿐이라 멈춘다(`test_weak_search_still_stops_uncertain_non_plan`).

## 5. 바뀐 동작 — 전후 측정(API 0)

실색인 + mock LLM으로 쟀다. 백테스트 5편은 실행 파일에 남은 sol 판정(적합성 판정·요소, 검색어 단계 판정·검색어)을 그대로 재생했다. W·N은 기본 mock 응답이다. 전은 main `f6095f5`(임시 worktree), 후는 이 브랜치다. mock 카드 합성은 규칙 응답이라, 계획서 줄 키워드가 없으면 카드를 못 만든다. 그래서 카드 수 자체는 품질 지표가 아니다.

mock 테스트로 고정한 동작(`tests/e3/test_short_input.py`, 83개):

- 짧은 입력: 백테스트 판정을 재현한 `live_like`에서 카드 1장 이상, `input_quality.level=warn`, `research_gate.status=proceeded_on_similar_work_evidence`, `suitability.thin_input=True`, `queries_source=rule`, 원문 대조 ok, 계약 스키마 통과.
- 화면: `_status.input_quality.level=warn`, 라벨은 "입력이 짧아 결과 신뢰도 낮음 · 검색어 규칙 대체 · 적합성 보류였으나 유사 연구 근거로 진행", notices 맨 앞에 경고 문구, ui_view 계약 통과.
- 거절: LLM 호출 0(`llm.calls == []`), 사유는 "입력이 너무 짧아 분석하지 않았다(규칙 판정, LLM 호출 없음) — 연구 질문·방법·데이터·평가를 더 적어 주세요", 화면 라벨은 "입력이 너무 짧아 분석하지 않음".
- 범위 밖: 기본 mock에서 호출은 fitness 1회뿐이고 유사 연구 0편. LLM이 "보류"라고 해도 멈춘다. 검색이 8편 모두 관련도 0.7로 나오는 최악의 가짜 백엔드에서도 `rule_on_topic` 조건에서 멈춘다.
- 낮은 유사도: 하한을 넘은 논문이 0편이면(경고 단계) 상위 k편을 쓰고 표시한다. 보통 단계 계획서에는 쓰지 않는다.
- 분야 수준 카드: 합성이 []를 내면 규칙 카드 1~3장이 나온다(generator rule, `plan_lines=[]`, 근거는 원문 구간 그대로, synthesize_cards degraded, 결과 status degraded, notices에 "LLM 생성 아님"). 보통 단계 계획서에는 만들지 않는다.
- 새 정규식(`_UNIT_SPLIT`, `_DEMONSTRATIVE`)과 환산 함수: 적대 입력 9종(20만 자)에서 각각 0.2초 미만.

## 6. 재실행하면 예상되는 호출 수·비용(sol $2/1M 입력, $10/1M 출력, 실행 안 함)

토큰은 E5-L2d §8의 실측 크기로 잡았다. 추출 묶음 하나는 입력 약 3천·출력 약 1.3천 토큰이다(low 추론 포함). 카드 합성은 후보 240개라 입력 약 2.6만·출력 약 4천이다. v1 단계는 호출당 입력 약 5천·출력 약 2.5천, 적합성·검색어는 호출당 입력 약 1.5천·출력 약 0.5천이다.

| 재실행안 | 호출 | 토큰(입력 / 출력) | 비용 |
|---|---|---|---|
| A. 0장 3편만(같은 계획서) — 이 방침에서 ihHe는 거절이라 **호출 0** | SFCH ≈ 28(적합성 1 + 검색어 1(v2라 캐시 미적중) + 추출 21 + 합성 1 + v1 3~5), o1Ii ≈ 38(추출 31) → **약 62~72** | 약 0.26M / 0.10M | **약 $1.5**(범위 $1.1~2.2, 추론 토큰에 따라) |
| B. n=5 전부 다시(검색어 v2로 유사 연구가 바뀌어 추출 캐시가 모두 빗나가는 최악) | A + VqEE ≈ 35 + U3PB ≈ 36 → **약 135~145** | 약 0.55M / 0.21M | **약 $3.2**(범위 $2.5~4.5) |
| 참고: 실서비스 입력 1건 | 거절 0회 / 범위 밖 1회(적합성) / 경고 단계는 보통 계획서와 같은 30~40회 | 경고 1건 ≈ 0.12~0.15M / 0.05M | 거절 $0, 범위 밖 약 $0.005, 경고 약 $0.7~0.9 |

- 분야 수준 카드는 규칙이라 호출을 늘리지 않는다. 합성 지시문 추가분(`SHORT_INPUT_NOTE`)은 호출당 약 100토큰이다.
- 검색어 지시문 v2는 검색어 캐시 키를 바꾼다. 데모 계획서도 다음 실행에서 계획서당 검색어 1회가 더 든다(약 $0.005).
- 재실행 결과는 사전 등록 결과와 섞지 않고 "사후 재실행"으로 표기해야 한다(E5-L2d와 같은 의견).

## 9. 결정(스펙이 모호해서 고른 것)

- **거절 기준을 200자에서 환산 80자로 낮췄다**(§3). 한국어가 영어보다 글자 수가 적은 점과, 기존 테스트의 "아이디어 구상" 입력을 반영했다. 한 문장이라도 요소가 3개 이상이면 경고로 둔다.
- **범위 밖 글은 분량 단계에서 거절하지 않는다.** 무관 표지가 있으면 `no_topic`을 건너뛰고, 지금처럼 적합성 판정이 "연구계획서가 아니다"로 거절한다. 기존 테스트의 사유 문구를 지키려는 것이다.
- **진행 조건에 검색 근거를 넣었다**(PM 힌트). E5-L2d P1은 uncertain이면 무조건 진행한다. 여기서는 경고 단계, 규칙 신호가 무관한 글이 아님, 관련도 0.50 이상 3편 이상을 모두 요구한다. 그래서 E5-L2d가 바꾸자고 한 기존 테스트 기대값(`test_fit_overrides_query_axes_rejection_but_uncertain_does_not`)은 바꿀 필요가 없었다.
- **분야 수준 카드는 규칙 합성으로 했다.** 짧은 입력은 먼저 LLM 합성에 `SHORT_INPUT_NOTE`를 붙여 기회를 주고, 그래도 0장일 때만 규칙 카드를 만든다(추가 호출 없음). 규칙 결과라 synthesize_cards를 degraded로 두고, 카드 generator는 rule, 제목은 "분야 공통 위험: …"이다. 계획서 줄에는 묶지 않는다(`plan_lines=[]`). AGENTS의 "규칙은 비상 경로" 원칙에서 벗어나므로 `docs/decisions.md`에 한 줄이 필요하다(PM 소유라 쓰지 않음, §11 제안).
- 낮은 유사도 대체는 경고 단계이면서 규칙 신호가 무관한 글이 아닐 때만 쓴다. 보통 단계 계획서는 예전처럼 "유사 연구 검색 결과가 0건이다"로 끝난다.
- 기준값은 설정 키가 아니라 모듈 상수로 두었다(`fitness.MIN_CHARS=80`, `WARN_EFF_CHARS=600`, `HANGUL_WEIGHT=2.5`, `pipeline.RESEARCH_GATE_MIN_TOP=0.50`, `RESEARCH_GATE_MIN_WORKS=3`). `.env.example`에 새 키를 더하지 않으려는 것이다.

## 10. 못 한 것

- 실제 sol로 확인하지 못했다(재실행 금지). 특히 다음 세 가지는 라이브에서만 확인할 수 있다: 검색어 지시문 v2가 배경만 있는 글에 검색어를 주는지, `SHORT_INPUT_NOTE`로 LLM이 카드를 내는지(분야 수준 규칙 카드까지 가는 비율), 경고 단계 입력의 카드 품질.
- VqEE(보통 단계)는 mock 합성에서 0장이다. 실측(sol)에서는 3장이었으니 mock 한계로 보인다. 분야 수준 카드는 경고 단계에서만 만들기 때문에 보통 단계의 0장은 막지 않는다.
- 화면(`index.html`)에 입력 단계 배지나 "분야 수준 카드" 표시는 넣지 않았다(다른 빌더와 충돌). 지금은 공지 상자의 라벨·문구와 카드 제목으로 보인다.
