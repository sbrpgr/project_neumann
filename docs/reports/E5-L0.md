# E5-L0 보고서 — 근거 연결 검사기

- 빌더: Claude Opus 5.5 · 브랜치 `task/E5-L0`
- 소유: `eval/linkage.py`, `tests/e5/test_linkage*.py` (+ 이 보고서)

## 무엇을 했나

1. `eval/linkage.py`
   - `check_result(result, source_lookup) -> LinkageReport`. 카드 1장이 인용한 excerpt id 1개를 "근거 링크" 하나로 보고, 링크마다 다음을 모두 잰다.
     - excerpt id가 `result.evidence`에 있다(같은 id에 다른 내용이 두 번 있으면 실패)
     - `source_url`이 비어 있지 않은 http(s) URL이다
     - `source_lookup(source_id)`가 원문을 돌려준다
     - `원문[start:end] == text`, 글자 그대로 비교한다(strip·정규화 없음). 빠진 오프셋은 `is None`으로만 본다. 오프셋 0은 정상값이다
     - `sha256(text) == text_sha256`. `source_sha256`이 있으면 `sha256(원문) == source_sha256`도 본다
   - 보고: 근거 연결률(통과 링크/전체 링크), 카드 통과율(모든 근거가 통과한 카드/전체 카드), 폐기율, 실패 목록(카드 id, excerpt id, 사유 키, 설명), 사유별 건수, 판정(`pass`/`fail`/`no_cards`)
   - 모델 생성자 검사를 믿지 않는다. dict 입력은 계약 검증 없이 필드를 직접 읽는다. 그래서 조작된 JSON(해시만 틀림, URL 빔)도 예외 없이 실패로 센다. 계약 검증을 통과했는지는 `contract_valid`에 따로 남긴다. 모델 입력도 필드를 다시 잰다(`model_construct`로 검증을 건너뛴 모델 포함)
   - 폐기율 없는 결과는 `drop.available=false`, `rate=null`로 두고 "폐기율 없음"을 `drop.note`, `notes`, 요약 줄에 적는다
   - 카드 0장이면 연결률을 1.0이 아니라 `null`로 두고 판정을 `no_cards`로 한다(공허한 100% 방지)
   - CLI: `python -m eval.linkage --result <result.json> [--sources <파일|폴더> ...] [--out <report.json>] [--allow-empty]`. 종료 코드는 0 통과, 1 실패 또는 카드 0장(`--allow-empty`면 0), 2 입력 오류
   - `load_sources(paths)`: `.jsonl` 레코드(ReviewEvent·AuthorResponse·Decision·PostStatus의 JSON), `.json` `{id: 원문}` dict, 폴더를 읽는다. 폴더에서는 원문 형식이 아닌 파일(결과 JSON 등)과 발췌 레코드(`excerpt_id` 있음)를 건너뛴다. 같은 id에 다른 원문이 있으면 오류다
2. 테스트 `tests/e5/test_linkage.py`(32건, models로 만든 작은 결과)와 `tests/e5/test_linkage_fixtures.py`(7건, E0b 공용 fixture)

## PM용: `check_result` 인터페이스 (verify.py 연결용)

```python
from eval.linkage import check_result, load_sources

report = check_result(result, source_lookup)
#   result: PremortemResult 또는 그 model_dump(mode="json") dict
#   source_lookup: source_id -> 원문. dict 또는 함수(없으면 None 반환이나 KeyError).
#                  원문은 str 또는 .text/["text"]가 str인 객체(ReviewEvent 등)
#   예외: result 타입이 틀릴 때만 TypeError. 조회 예외·조작 입력은 실패로 집계한다
report.passed          # verdict == "pass" (카드 ≥1, 모든 링크·카드 통과)
report.verdict         # "pass" | "fail" | "no_cards"
report.linkage_rate    # 링크 단위, 카드 0장이면 None
report.card_pass_rate  # 카드 단위(04_평가_명세 §2.2의 rate와 같은 단위)
report.drop.available, report.drop.rate   # 폐기율 없으면 False, None
report.failures        # [LinkFailure(card_id, excerpt_id, reasons, detail)]
report.summary()       # 한 줄 요약(인용 원문 안 넣음)
report.model_dump(mode="json")            # 보고서 JSON(passed 포함)

sources = load_sources(["tests/fixtures"])  # 파일·폴더 → {source_id: 원문}
```

verify.py 예시(PM 판단): `check_result(load_fixtures().premortem_result, load_sources([FIXTURES_DIR]))`가 `passed`인지 보고, 조작본 1건이 `linkage_rate < 1.0`인지 함께 본다. 음성 대조 결과(카드 0장)는 `verdict == "no_cards"`로 따로 다룬다.

## 결정 (스펙이 모호하거나 문서끼리 달라서 고른 것)

1. **연결률 단위:** 과제 파일의 "근거 연결률(통과/전체)"는 링크(카드×인용 excerpt id) 단위로 쟀다. 04_평가_명세 §2.2의 `rate = ok / n(표시된 카드 수)`는 카드 단위라 `card_pass_rate`로 따로 낸다. 둘 다 보고한다
2. **비교 방식:** 04 §2.2는 `.strip()` 비교를 적었지만 과제 파일과 AGENTS.md("원문 오프셋과 글자 단위로 같아야")를 따라 글자 그대로 비교한다. 더 엄격한 쪽이다
3. **8개 필드:** 04 §2.2의 `snapshot_date·model·prompt_version`은 Excerpt 계약에 없어서 검사하지 않는다(아래 제안)
4. **폐기율 정의와 위치:** 과제 파일(지적 단위: 버린 지적 / 전체 지적)을 따랐다. 04 §2.2는 카드 단위 폐기율이다. 계약에 자리가 없어서 키를 정했다. `result.verification`의 `findings_dropped`와 `findings_total`(또는 `findings_kept`, 이때 전체=kept+dropped)을 먼저 읽는다. 없으면 `stages[].counts`의 같은 키를 모두 더한다. 수가 이상하면(음수, dropped>total, 정수 아님, total 0) 비율을 내지 않고 사유를 적는다
5. **카드 0장:** 연결률 `None`, 판정 `no_cards`, `passed=False`. 공허한 1.0을 내지 않는다. 음성 대조용 CLI는 `--allow-empty`
6. **`source_sha256`이 없는 발췌:** 계약상 선택 필드라 실패로 보지 않는다. 구간 대조는 하고 `source_hash_unchecked`로 센다
7. **원문 없음:** `--sources`가 없거나 조회가 실패하면 그 링크는 실패다(`source_not_found`/`source_lookup_error`). 인용문 자신을 원문으로 쓰는 순환 대조를 막는다
8. **계약 위반 입력:** dict가 PremortemResult 검증을 통과하지 못해도 검사를 계속한다. `contract_valid=false`와 첫 오류 위치를 `notes`에 남긴다(입력값은 적지 않는다)
9. **실패 설명의 인용 조각:** `text_mismatch` 설명에는 원문·인용 앞부분을 60자까지 넣는다(공개 심사평 조각). 요약 줄에는 넣지 않는다

## 못 한 것

- `scripts/verify.py` 연결: PM 소유라 손대지 않았다. 위 인터페이스로 연결하면 된다
