## run_premortem 인터페이스 (E4 연결용)

```python
from neumann.pipeline import run_premortem
result = run_premortem(plan_text, session_id=None)   # -> neumann.models.PremortemResult
# 선택 인자: provider="openai"|"mock"|"off", llm=<provider 객체>, backend=<EvidenceBackend>,
#            k=10, exclude_work_ids=set(백테스트 누출 제거), min_similarity=0.0, cache_dir=Path|None
```

- 기본 backend는 E2 실색인(`IndexBackend`). 색인을 못 열면 예외 대신 카드 0장 + 사유("유사 연구 색인을 열 수 없어…")
- `result.status`: 단계 중 degraded/error가 있으면 `"degraded"`(모델이 강제)
- `result.stages`: `plan_normalize`(INPUT) → `query_axes`(INPUT) → `search`(EVIDENCE) → `extract_issues`(EVIDENCE) → `synthesize_cards`(RISK) → `verify_evidence`(REVIEW). 각 `state`(ok/degraded/skipped/error), `detail`(비상 경로면 "비상 규칙 경로: <사유>"), `impl`(`openai:gpt-6-astra`, `fallback:…`, `neumann.index.search:search`), `elapsed_s`, `counts`
- `result.risk_cards[]`: `RiskCard`(card_id, risk_code, title, why_applies{text, plan_lines}, evidence=[excerpt_id…], works, score{similarity, frequency, severity, confidence, total, weights}, **generator: astra|rule|mock**, model). 점수 내림차순, 최대 8장
- `result.evidence[]`: 카드가 인용한 `Excerpt`(source_id=review_id, start/end=심사평 원문 절대 오프셋, text=원문 조각, source_url=심사평 링크). 모두 원문 대조 통과분
- `result.similar_works[]`: `SimilarWork`(work_id, similarity, title, url, venue, year)
- `result.plan`: `PlanDocument`(줄 번호, 마스킹 후 본문). 영속 저장은 `result.dump_persisted()`
- 카드 0장이면 `result.risk_synthesis["no_card_reason"]`와 `result.notices`에 사유(예: "입력이 연구계획서가 아니다(astra 판단: …); 유사 연구 검색 상위 점수 …")
- `result.plan_checks`: `suitability`(is_research_plan, reason, reason_lines, generator), `queries`(astra 검색어), `search`(top_score, scores, backend_status)
- `result.verification`: `findings_total·findings_kept·findings_dropped·findings_drop_rate·findings_drop_reasons·findings_rule`(E5-L0 `eval.linkage`가 읽는 키), `quotes_total·quotes_verified·linkage_rate`
- `result.risk_synthesis`: generator, fallback_reason, pool_size, drops, `tags`(카드 근거마다 RiskTag: 그 근거를 astra가 태깅했는지 규칙이 태깅했는지), score_formula
- `result.manifest`: llm_provider, llm_model, backend, prompt_versions, timings_s, total_s
- 카드 제목·이유는 한국어(astra). 규칙 카드는 제목에 "(규칙: …)", 이유에 "비상 규칙 경로:"가 들어간다 → 화면 강등 배지는 `card.generator == "rule"` 또는 `result.status == "degraded"`로

1. **별칭 id:** 호출 안에서는 발췌를 `s1…`, 카드 풀을 `E1…`, 논문을 `P1…`로 보낸다(스키마 enum이 짧아지고 출력 토큰이 준다). 코드가 실제 excerpt_id로 되돌린다. 모르는 별칭은 `unknown_excerpt_id`로 폐기
2. **R9:** EX-4 계약대로 enum에는 두되 지시문에서 금지하고, 심사평에서 나온 R9는 `r9_from_review`로 폐기(택소노미 B9: 사후 기록 전용). 카드 유형 enum은 R1~R8
3. **연구계획서 여부:** astra ① 호출에 `is_research_plan`·근거 줄을 함께 받는다(추가 호출 없음). 아니면 검색까지만 하고 추출·합성을 건너뛰어 카드 0장 + 사유(판정 근거 + 검색 상위 점수). 비상 경로는 연구 어휘 4회 미만이면 아님
4. **계획서 줄 없는 카드 거부:** 모델 카드에 유효한 계획서 줄이 하나도 없으면 버린다(`card_no_plan_lines`). 외부 논문 대상을 계획서로 끌어오는 함정(P027) 방지
5. **하위 구간 근거:** 모델이 문장 일부 위치를 주면 같은 원문의 하위 Excerpt(절대 오프셋, id=`Excerpt.make_id`)를 만든다. 대조는 심사평 전문으로 다시 한다
6. **단어 경계 넓힘:** 범위 안인데 단어 중간에서 잘린 구간은 넓혀 쓰고 `spans_snapped`로 센다(폐기 아님). 범위 밖은 폐기
7. **점수:** `product_v1` = similarity(카드 근거 논문의 검색 점수 평균) × frequency(그 유형 부정 지적이 나온 논문 수 / 분석한 논문 수) × severity(택소노미 기본 S5=1.0, S4=0.8, S3=0.6) × confidence(근거 지적 신뢰도 평균). 가중치 칸에는 지수 1.0을 남김. 보정은 L1
8. **캐시:** openai provider의 성공 응답만, 키 = sha256(지시문 판·모델·추론 강도·[excerpt_id, text_sha256]…). 읽을 때도 같은 검증을 다시 한다
9. **provider `off`:** 설정(`config.py`)은 openai|mock만 받으므로 `off`는 `run_premortem(provider="off")`·명령줄 `--provider off`로만 켠다(비상 경로 확인용)
10. **fixture 코퍼스 자체 작성:** 공용 fixture(`tests/fixtures`, E0b)는 초록이 없어 검색 분별력이 약하다. 분야 대비 검사용으로 `tests/e3/corpus.py`를 따로 만들었다. 공용 fixture로도 데모 계획서·음성 대조 한 쌍을 검사한다
11. **추출 동시 호출:** 실색인 실측(1,435문장 → 42묶음, 동시 10에서 85초)을 보고 기본값을 묶음 50·동시 24로 올림(32묶음 39초). 429는 아직 보지 못했다
12. **E2 코드:** 이 브랜치에는 E2가 아직 병합되지 않아, 실색인 실측은 E2 브랜치 커밋(`task/E2-L0` fcdcfda)의 `neumann/index`를 스크래치에 읽기 전용으로 꺼내 붙여 돌렸다(저장소에는 넣지 않음). 제품 코드는 인터페이스(`search`, `store.get_*`, `taxonomy.tag_excerpts`)만 부른다

## 못 한 것

- E2가 main에 들어오지 않아 `IndexBackend` 경로의 자동 테스트는 fixture로만 돈다(실색인은 위 실측 스크립트로 확인). E2 병합 뒤 `NEUMANN_LIVE_TESTS=1 pytest tests/e3/test_live_astra.py`가 실색인을 자동으로 고른다(검색이 되면 실색인, 아니면 fixture)
- 추론 강도 튜닝은 query=low, extract=low, synth=medium 한 조합만 쟀다. L1에서 지연·품질을 나눠 재기
- 폐기율은 0.4~0.5%로 낮다. 대부분 위치를 null(문장 전체)로 받기 때문이다. 하위 구간 품질(단어 경계 넓힘 41건)은 L1에서 다시 본다
- 검색 결과가 astra 검색어에 따라 조금씩 바뀐다(같은 계획서 두 번: 상위 점수 0.511 → 0.540, 카드 유형 구성도 달라짐). 데모 계획서의 핵심 위험인 **분할 누수(R3) 카드가 두 번째 실행에서는 나오지 않았다**(유사 연구에 누수 지적 논문이 덜 걸림). 결정성·재현이 필요하면 L1에서 검색어 캐시(계획서 해시 키)와 카드 후보 유형 보강(추출된 지적 유형 빈도를 카드 지시문에 힌트로) 검토
- 지시문 v3(택소노미 포함) 뒤 plan.md는 1회만 쟀다. 여러 번 돌려 카드 구성의 분산을 재지 않았다
- 개인정보 마스킹은 최소판(이메일·ORCID는 models, 전화번호·주민번호 형태는 pipeline). 이름 마스킹은 없음(E3-L1c)
