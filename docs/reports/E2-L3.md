# E2-L3 보고서 — 확대 코퍼스(2,128편) 색인을 새 폴더 `data/index_l3/`에

- 브랜치: `task/E2-L3`(main f636fad 기준) · 빌더: Claude Opus 5.5 · 검증: Sonnet 5.5
- 입력: 공유 `data/processed_l3/`(E1-L3, 브랜치 `task/E1-L3`) · 출력: 공유 **`data/index_l3/`**(커밋하지 않음)
- **현재 색인 `data/index/`는 건드리지 않았다**(빌드 전후 `manifest.json` sha256 `a0d1cf87…c38c62` 같음, 파일 목록·크기·시각 같음).

## 무엇을 했나

| 파일 | 내용 |
|---|---|
| `scripts/build_index_l3.py` | E2-L0 `scripts/build_index.py`를 그대로 불러 `processed_l3 → index_l3`로 빌드. ① 출력이 현재 색인(`{DATA_DIR}/index`, `NEUMANN_INDEX_DIR`)이나 입력 폴더면 **거부**(rc 2) ② 색인 입력 해시를 E1-L3 `corpus_manifest.json` `outputs` sha256과 대조(다르면 rc 1) ③ CUDA OOM이면 배치를 반으로 줄여 재시도 ④ manifest에 `corpus`(E1-L3 요약·해시 대조)·`groups`(AI4S/일반 ML별 논문·심사평·문장 수)·`l3.switch`를 덧붙임 |
| `scripts/build_index_compare.py` | 두 색인을 읽어 문장 전량 오프셋 재대조, 데모 계획서 3건(`tests/fixtures/plans/`)의 상위 k편 전후 비교(겹침·새로 든 논문의 그룹·순위 이동·같은 논문 dense 차), 무관한 글 바닥 점수. `--json`·`--md` |
| `tests/e2/test_l3_index.py` | 10건: 현재 색인 덮기 거부(경로 표기 달라도·`NEUMANN_INDEX_DIR`), 빌드·manifest 덧붙임, 해시 불일치 실패, corpus_manifest 없음 표시, OOM 판별, 비교 스크립트(가짜 두 색인에서 새 일반 ML 논문이 1등으로 드는 것을 잡는지), 순위 기록, **실제 `index_l3` manifest 검사**(있을 때만) |

색인 코드(`src/neumann/index/`)는 고치지 않았다(E2-L1 작업 중). `build_index.py`에는 이미 `--processed`·`--out` 인자가 있어 그것도 고치지 않고, 새 파일 두 개로 감쌌다.

**판정(눈으로 본 것)**

1. **전해액 데모(주 데모)는 거의 그대로다.** 겹침 9/10, 상위 4편 순위 같음, 1등 점수 0.3704 → 0.3702. 새로 든 1편(Rethinking the Expressiveness of GNNs, 5위)도 GNN 논문이다. 영어 질의도 겹침 8/10이고 새로 든 2편도 AI4S다.
2. **분야 밖 데모(fMRI·의료영상)는 일반 ML 논문이 많이 들어온다**(한국어 전문 질의 6편·3편, 영어 7편·9편). 뇌 인코딩·EEG·발작 분류처럼 더 가까운 이웃도 생기지만, 무관한 일반 ML(Neural Program Induction 1위, Neural Collapse 3위 등)도 섞인다.
3. **원인: 한국어 전문 질의의 점수 폭이 좁다.** 현재·확대 모두 상위 10편 점수가 0.347~0.373(1등과 10등 차 0.01~0.02)이라, 1,000편이 더 들어오면 비슷한 dense 점수의 논문이 쉽게 끼어든다. 무관한 글 1등은 0.243 → 0.249로 여전히 관련 질의(0.35 이상)보다 확실히 낮다.
4. **같은 논문의 dense 점수는 두 색인에서 같다**(최대 차 0.00034, fp16 저장 오차 수준). 점수 차이는 BM25 쪽(idf·평균 길이)에서만 난다 → 현재 색인 기준으로 잡은 점수 하한·가중치(E2-L1)는 확대 색인에서 한 번 다시 재야 한다.

## 결정 (스펙이 모호해서 고른 것)

1. **`build_index.py`를 고치지 않고 감쌌다.** 이미 `--processed`·`--out`을 받는다. E2-L1과 충돌하지 않게 새 파일에 "현재 색인 덮기 거부 · E1-L3 해시 대조 · manifest 덧붙임"만 넣었다.
2. **현재 색인 보호**는 경로 비교(`resolve` + 대소문자 무시)로 `{DATA_DIR}/index`와 `NEUMANN_INDEX_DIR` 둘 다 막는다. 빌드 중 `NEUMANN_INDEX_DIR`을 index_l3로 켜 둔 채 돌리면 그것도 막히므로, 빌드는 이 변수 없이 돌린다.
3. **배치 16 유지**: 빌드 직전 여유 VRAM 4.7GB, E2-L0 실측 최대 할당 1.35GB. 다른 빌더와 나눠 쓰는 것을 생각해 키우지 않았다(임베딩 43s라 키울 이득도 작다). OOM이면 자동으로 반씩 줄이게 했다(이번엔 안 일어남).
4. **비교 질의는 계획서 전문 한 건**(E2-L0 방식). astra 검색어는 실제 호출이 금지라 못 넣었고, 대신 손으로 쓴 영어 한 줄을 "보조"로 따로 표시했다(LLM 생성이라고 쓰지 않는다).
5. **그룹 판정**은 확대 색인 `works.fields`에 `general_ml`이 있는지로 한다(E1-L3 `selection.jsonl`의 `group`과 같은 규칙, manifest `groups` 합계 = `corpus.selection.by_group`로 테스트가 확인).
6. manifest에 덧붙인 키(`corpus`, `groups`, `l3`)는 `IndexStore.load`가 무시하는 추가 키라 색인 형식(`neumann-index-v1`)은 같다.
