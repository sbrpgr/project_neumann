## mock 표기 정직성

- 실제 분석으로 오해될 수 있는 것: 헤더 "분석 파이프라인 연결"과 입력 화면 "OpenAI API로 전송" 고지(Q2-7). mock 서버로 입력 화면을 찍으면 실제 서비스처럼 보인다. 사전 계산본 라벨 "사전 계산본(2026-09-30 18:55 KST)"도 fixture라는 표시가 화면에 나오는지는 이번에 확인하지 못했다(API에는 `source=fixture`).

- ZIP에 "astra" 3회(README의 "JSON 값 generator: "astra"는 계약 이름" 설명 줄과 JSON 값), "OpenAI" 2회("제품 LLM(OpenAI, 모델은 manifest 참조)" 설명 줄). 사람용 문서의 카드·모델 표기에는 없다.

## 07:30 녹화 가능 여부

**판정: 이 core-final 후보 단독으로는 대표 07:00 기준의 전체 흐름(입력 → 분석 → 재탄생 → 확정·검증) 녹화가 불가하다. 1단계(입력 → 분석 → 리포트 → 근거 → 내보내기)만이라면 아래 조건에서 녹화할 수 있다.**

차단 항목:

1. **재탄생(수정 권고)·확정 화면 없음(Q2-1).** API만 있다. `task/FIN-UI`·`task/E4-L4r`가 main에 들어간 뒤 같은 점검을 다시 하거나, 2·3단계는 8172 목업으로 찍어야 한다.
2. **녹화 창의 CSS 폭은 1181 px 이상(Q2-2).** 그 아래에서는 근거 서랍을 누를 수 없다. 1440×900 화면이면 Windows 배율 100%, 브라우저 확대 100%, 창 최대화를 녹화 전에 확인한다(125% 배율이면 1152 px로 고장). 수정되기 전까지는 운영 규칙으로 막는다.
3. **서버를 띄울 때마다 분석 1회로 예열(Q2-5).** 재기동 뒤 첫 분석은 최대 158초였고, 그동안 "약 1초 남음"에 멈췄다가 "약 89초 남음"으로 되돌아간다.
4. **mock 서버로 찍는다면 헤더·고지가 실제 분석처럼 보인다(Q2-7).** 8020 라이브로 찍거나, mock 장면에 자막을 넣는다.
5. 장면에 HWPX 업로드를 넣는다면 `task/E4-L2h` 병합이 필요하다(Q2-3). 범위 밖 거절 장면을 넣는다면 머리 문구가 "입력이 짧아…"로 나온다(Q2-4).

녹화에 보이지만 막지는 않는 것: 리포트 날짜가 "2026-09-30"(Q2-10), "김대운"(Q2-13), mock이면 "일부 단계 강등"(Q2-14).
