## 무엇을 했나

1. `src/neumann/api/main.py` (FastAPI)
   - `GET /` → `webui/index.html`(no-store), `GET /fonts/...` → 로컬 폰트(StaticFiles)
   - `GET /health` → `{"status":"ok","version","pipeline":{state,reason,mode,label},"stages":{단계: {available, modules}}}`. 단계별 모듈을 실제로 import 해 보고 `ok / missing / error`를 적는다
   - `POST /premortem`, `POST /premortem/view`: 입력 `{"plan_text": str(1~200,000자, 공백만이면 422), "filename"?: str}`
   - `neumann.pipeline.run_premortem`을 요청마다 **지연 import**. 동기·async 둘 다, 시그니처에 `filename`이 있으면 넘긴다. 동시 실행 2
   - 모듈이 **없으면**(ModuleNotFoundError, 그 모듈 자체): 공용 fixture `tests/fixtures/premortem_result.json`(가짜 데이터)을 `PremortemResult`로 검증한 샘플을 돌려준다. 응답에 `sample: true`, `status: "degraded"`, `notices[0]`="분석 파이프라인 미연결(샘플 데이터): …", `stages[0]` = `run_premortem · unavailable · fallback:sample`. 뷰에는 `_status.label`="분석 파이프라인 미연결(샘플 데이터)"
   - 모듈이 **있는데 import가 깨지거나 실행이 실패하면** 샘플로 숨기지 않고 500 + 오류 상태. 사유에는 예외 종류와 파일:줄만 싣고 예외 메시지는 싣지 않는다(키·헤더 유출 방지)
2. `src/neumann/api/view.py`: `build_ui_view(result, *, filename, sample, pipeline_state, error, input_info)` → ui_view dict + `_status`. 예외를 던지지 않는다(섹션별 방어 + 최후 방어선). 끝에서 `jsonschema` Draft-07로 `contracts/ui_view.schema.json` 검증, 위반이면 빈 뷰 + 오류 상태(`contract_errors`)로 바꾼다. `validate_ui_view(view)` 공개
3. `src/neumann/webui/index.html`: 목업 `web/index.html` 스타일을 그대로 가져오고 하드코딩 DATA 대신 `POST /premortem/view` 응답을 렌더. 입력(직접 입력 붙여넣기 + MD·TXT 파일 읽기) → 분석(경과 시간, 응답 후 단계 기록) → 리포트(요약·유사 연구 지도·위험카드[인용 + 원문 링크 + 생성 방식]·추적, 데이터가 있으면 예상 심사평·체크리스트). 오른쪽 근거·계획서 패널
4. 폰트 5종을 `webui/fonts/`로 복사(각 폴더 OFL.txt·Pretendard LICENSE 포함), `@font-face`로 로컬 서빙. CDN·JSZip 제거. 헤더 실명 배지 유지

## build_ui_view 입력 형식 (E3 전달용)

**`PremortemResult`(models.py)를 그대로 넘기면 된다**(모델 객체 또는 `model_dump(mode="json")` dict). 읽는 필드:

| 결과 필드 | 화면에서 쓰는 곳 | 비고 |
|---|---|---|
| `status`, `notices`, `generated_at`, `pipeline_version`, `session_id`, `plan_id` | 상태 상자, 추적 | `status`가 degraded/error면 상단에 표시 |
| `plan.lines[{no,text}]` (또는 `plan_stats.lines[{n,t,h}]`) | 계획서 스트립·패널, 카드의 "계획서 대응" | 줄 번호는 결과 번호 그대로. 빈 줄은 화면에서만 뺀다. `#` 줄은 제목 표시 |
| `similar_works[{work_id,title,url,venue,similarity}]` | 유사 연구 지도(원문 링크) | `decision`, `rating` 키가 있으면 결정·평점을 보여 준다(없으면 "미정", "–") |
| `evidence[Excerpt]` | 인용문(`text` 그대로), 원문 링크(`source_url`), 오프셋·해시 | 논문 대조: `work_id` 키가 있으면 그것, 없으면 `source_url`과 유사 연구 `url`을 같은 host·path·`id` 파라미터로 맞춘다 |
| `risk_cards[RiskCard]` | 위험카드 | `title`, `risk_code`/`subcode`, `why_applies.text`·`plan_lines`, `score.{similarity,frequency,severity,confidence,total}`, `evidence`(발췌 id), `works`, `generator`(astra/rule/mock 그대로 화면 표기). 심각도는 `score.severity`(0~1)×5 반올림(1~5). `actions: [str]`가 있으면 "착수 전 예방 행동" |
| `expected_review{strength,weakness,request: [{text, evidence:[발췌 id]}], audit{generated, dropped:[{reason,text}]}}` | 예상 심사평(L1) | 화면 근거 번호로 풀리지 않는 문장은 내보내지 않는다 |
| `checklist[{id, action, risk_code, decision(채택/보류/기각), note}]` | 체크리스트(L2) | |
| `stages[StageStatus]` | 분석 화면 단계 기록, 추적 | `phase`로 묶는다. ok가 아니면 상태 상자에 이름·사유 |
| `manifest{model_id, model_provider}` | 추적 | |
| `empty_reason`(선택) | 카드 0장일 때 사유 | 없으면 RISK 단계의 사유 → 기본 문구 |

규칙: 인용 번호에 걸리지 않는 카드(근거 발췌가 `evidence`에 없음)는 화면에서 빠지고 `_status.dropped.cards_without_evidence`에 센다. 생성 방식이 astra가 아닌 카드가 하나라도 있으면 `_status.degraded = true`.

## 결정 (스펙이 모호해서 고른 것)

- **샘플의 출처**: 처음에는 목업 DATA를 옮긴 샘플을 만들었다가, main에 E0b 공용 fixture가 병합된 뒤 그것으로 바꿨다(스펙 문구 "fixture로 만든 샘플 뷰"와 일치, 기획 키트 내용을 저장소에 두지 않음, 실제 `PremortemResult` 모양으로 매핑 검증). 목업 샘플 파일은 커밋 `ccd2415`에 한 번 들어갔다가 `14ea0e3`에서 지웠다(공개 심사평 인용이며 비밀값은 아님). 이력에서 없애려면 PM이 병합 때 squash
- **응답 확장 키 `_status`**: 계약 최상위가 추가 키를 막지 않아 밑줄 접두 키로 상태를 싣는다. 항목 안에도 화면용 추가 키를 둔다: works `u`(원문 URL)·`venue`·`sim`, ev `u`·`eid`·`off`·`sha`, cards `gen`·`id`. 계약 필수 키는 모두 채운다
- **헤더 알약**: 목업의 "비식별 · 세션 격리 · 종료 시 삭제"와 가중치 버튼은 아직 사실이 아니거나(L2 마스킹, L1 가중치) 준비 전이라 빼고, 그 자리에 `/health` 기반 파이프라인 상태를 둔다. 입력 카드의 "원문은 저장·학습에 사용되지 않습니다"와 분석 옵션·코퍼스 표기(가짜 숫자)도 뺐다(05_디자인_규칙 §6 안심 문구 금지, 정직성)
- **데이터 없는 섹션**: 예상 심사평·체크리스트는 데이터가 있을 때만 그리고 섹션 목차에서도 숨긴다. 내보내기 단계는 "준비 중"으로 비활성
- **파일 업로드**: L0는 브라우저에서 MD·TXT만 읽는다(서버 업로드 `/upload/plan`은 L1). PDF·DOCX·HWP는 "업로드는 준비 중 — 직접 입력에 붙여넣기"
- **결정 정보가 없을 때**: "그중 0편 거절"을 쓰지 않고 "결정 정보 없음"
- **근거 → 계획서 줄**: 발췌에 줄 정보가 없으면 그 발췌를 처음 인용한 카드의 첫 계획서 줄
- **예상 심사평의 `"map"` 인용**(목업 관례): 유사 연구가 있을 때만 근거로 인정
- **커밋 끝줄**: 프로젝트 규칙대로 `verify 통과` + `builder: claude-opus-5.5`로 끝낸다(Co-Authored-By 줄 없음)
- **실행 명령**: `python -m uvicorn neumann.api.main:app --host 127.0.0.1 --port 8000`은 `PYTHONPATH=src;.`(Windows 구분자)가 필요하다. `ui_shots.py`는 스스로 설정한다

## 제안 (계약 추가만, PM 판단)

1. `SimilarWork`에 `decision: str | None`(원문 문자열), `rating: float | None` — 지도·요약의 거절/채택 수를 지어내지 않고 보여 주려면 필요
2. `Excerpt`에 `work_id: str | None` — 지금은 URL 대조로 추정한다(유사 연구 목록 밖 논문은 제목을 모름 → "논문 미상")
3. `RiskCard`에 `severity: int(1~5)`와 `actions: list[str]` — 카드의 심각도 배지와 예방 행동
4. `ui_view.schema.json`에 `_status` 정의(선택 키) — 지금은 계약 밖 확장 키

## 못 한 것

- 실제 파이프라인 연결 화면: `neumann.pipeline`이 아직 없어 샘플로만 찍었다. 연결 경로는 가짜 `run_premortem`으로 테스트만 했다
- 목업의 다른 화면: 내보내기(L2), 가중치 모달(L1), 코퍼스 비율 행(`corpus`는 전부 null이라 숨김), 인쇄 스타일은 목업 CSS 그대로라 따로 검증하지 않음
- 분석 대기 화면의 실시간 단계 진행: 서버가 진행 이벤트를 보내지 않아 경과 시간만 보이고, 응답 뒤 단계 기록을 한 번에 보여 준다
- 모바일 폭(1180px 이하)은 목업 CSS 그대로, 따로 찍지 않음
