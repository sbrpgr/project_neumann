- **진행 중인 E5 백테스트와 조건이 갈린다.** 실제 astra 검색어 8건 재생에서 유사 논문 집합이 옛과 4~9/10만 겹친다(RRF·질의별 할당 때문). 이미 쌓인 `neumann_runs/real__*`(옛 검색)와 새 실행을 섞어 비교하지 않는다. 옛 조건을 재현하려면 `NEUMANN_SEARCH_FUSION=max NEUMANN_SEARCH_PER_QUERY_MIN=0 NEUMANN_SEARCH_ADAPTIVE_ALPHA=false NEUMANN_SEARCH_SCORE_FLOOR=0.0`(검증 2에서 옛 결과와 동일함을 확인).
- **`similar_works`의 순서가 유사도 내림차순이 아니다**(여러 질의일 때 결합 순서). `export.py`의 유사 연구 표(`#`·`rank` 열)와 화면 번호에서 "1번의 유사도 0.53, 3번 0.58"처럼 보인다. 카드 안의 논문 정렬(`cards.py`)은 자기가 유사도로 다시 정렬해서 영향 없음. 필요하면 E3가 `SimilarWork`를 만들 때 유사도로 정렬한다(E2 쪽 결정 4는 그대로).
- **`score` < 0.45인 결과가 나올 수 있다.** 하한은 `max(dense, score)`에 걸리므로 상태의 `score_floor: 0.45`와 결과 `score` 0.40~0.44가 같이 보인다(파이프라인에서 최소 0.401 확인). E3의 `min_similarity` 기본 0.0과 함께 쓸 때 헷갈리지 않게 알려 둔다.
- **E2 상태의 `top_score`는 결과 첫 편의 점수**라 최댓값이 아니다(예: 상태 0.532, 실제 최고 0.584). 파이프라인의 `plan_checks.search.top_score`는 결과에서 다시 최댓값을 구해 두 값이 다르다.
- 검색 상태의 `relevance`(verdict·근거)는 E3 결과와 E4 MCP 응답에 아직 실리지 않는다. 화면에 "관련 없음" 근거를 보이려면 E3(`_SEARCH_STATUS_KEYS`에 추가하고 사유 문구에 이어 붙임)와 E4(`SearchResult`에 verdict 필드) 후속이 필요하다. 지금은 0건 사유가 "검색 결과 0건"이고 MCP는 사유 없이 빈 목록이다.
- 파이프라인은 아직 `axes=`를 넘기지 않는다(`IndexBackend.search`가 질의만 전달). 축별 가중치는 E3가 `axes`를 넘길 때부터 쓰인다. 지금 통합 결과에는 축 가중치 효과가 없다.
- 사소한 것: `scripts/build_index.py`의 manifest `search_defaults.score_floor`가 이제 `null`(기본 하한이 모델별이라)로 기록된다. E2-L3의 `build_index_compare.py` 무관 글 점검은 새 하한 때문에 "1등 점수 None"만 나온다(오류 없음, 정보량만 줄어듦).

## 후속(병합을 막지 않음)

1. 데모 1 표적 BatteryML은 상위 10편 밖(22위)이다. 빌더가 적었듯 E3가 데이터·방법 축 질의를 구체적으로 만들거나 `per_query_min`을 올려야 한다. 이번 통합 실행(astra 스타일 영어 질의)에서는 카드가 정상 생성되므로 시연은 막히지 않는다.
2. 데모 1의 상위 10편 꼬리 1편이 임베딩 미세 차이(fp16 배치)로 바뀐다. 시연에서 "항상 같은 10편"이 필요하면 `precompute_demo`로 고정된 결과를 쓴다.
3. 짧은 한국어 일상 질의를 걸러 내려면 하한 숫자가 아니라 다른 신호가 필요하다. 후보: 질의 길이·어휘 적용률이 낮을 때 통과 편수 하한(예: ≥N편 넘어야 related), 질의 상위 k의 분포, 무관 세트 확대(일상 한국어 100건 이상). 실측 뒤에 정한다.
4. `.env.example`을 이 브랜치가 고치지 못하므로 PM이 병합 커밋에서 한다(조건 2).
