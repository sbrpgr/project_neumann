3. **manifest**(`data/processed_l3/corpus_manifest.json`)
   - 편수, 분야, 그룹, venue, 심사평 수(그룹별), 결정 분포, 일반 ML 층별 표본을 담는다.

4. **검사**

- 받기(`tests/e1/test_l3_fetch.py`, 가짜 HF 서버)
  - sha256이 다르면 파일을 두지 않고 `.part`도 남기지 않는다.
  - 이미 있고 맞으면 다시 받지 않는다. 손상됐으면 다시 받는다.
  - 키트 샤드의 리비전이 다르면 `same: false`로 표시한다.

## 다음 빌더(E2 색인 L3, E3, E5)에게

```python
from neumann.sources.corpus_l3 import load_corpus_l3, is_ai4science
corpus = load_corpus_l3()                  # NEUMANN_DATA_DIR/processed_l3 (E1-L0 Corpus 그대로)
ai4s = [w for w in corpus.works.values() if is_ai4science(w)]
general = corpus.works_in_field("general_ml")
```

- E2가 L3 색인을 만들 때는 입력만 `processed_l3`로 바꾸면 된다. 형식은 `data/processed`와 같다. 현재 `data/index/`를 덮지 말고 별도 폴더(예: `data/index_l3/`)에 만들 것을 권한다.
- 백테스트(E5)의 층화는 AI4S만 쓴다면 `is_ai4science`로 거른다. 일반 ML이 유사 연구 검색 상위를 차지하는지는 L3 색인에서 재 봐야 한다.

## 결정 (스펙이 모호해서 고른 것)

1. **E1-L0 모듈을 가져다 쓴다(복사하지 않는다).** 선별 키워드·정규화·신원 제거·레코드 형식을 E1-L0와 똑같이 두려는 것이다. 검증을 거쳐 E1-L0 키워드가 바뀌어도 따라간다.
   - E1-L0가 없어도 `corpus_l3` import와 샤드 받기는 된다. 조립 함수는 E1-L0가 없으면 분명한 `RuntimeError`를 낸다. 조립 테스트는 `importorskip`으로 건너뛴다.
   - 작업 중 E1-L0가 main에 들어와 main을 이 브랜치에 병합했다. 최종 상태에서는 건너뛰는 테스트가 없다.
2. **AI for Science는 1,128편이다(스펙의 "1,265편"이 아님).** 1,265는 사전 집계다. 실제 코퍼스는 E1-L0 키워드로 고른 1,128편이다. 같은 키워드를 써야 `data/processed`와 확대 코퍼스의 AI4S 부분이 같다.
   - E1-L0 검증이 추정한 선별 오탐(약 30%, 초록의 응용 예시에 걸린 논문)도 그대로 물려받는다.
   - 즉 `ai4science` 태그 논문 중 일부는 실제로는 일반 ML이다. 일반 ML 표본은 "키워드에 안 걸린 논문"에서만 뽑았다.
3. **일반 ML 1,000편, 층화 무작위.**
   - 편수: 합계 2,128로 기준 2,000을 넉넉히 넘긴다. 색인 비용은 약 2배로 억제한다(현재 색인은 논문 1,128편 기준).
   - 표본 방식: venue×결정 층 안에서 `sha256(f"{seed}:{paper_id}")` 순위로 고른다. 주제 편향 없이 결정 분포가 모집단과 같다.
   - `--general-ml N`으로 바꿀 수 있다. 후보 13,200편 전부도 된다.
4. **일반 ML은 ICLR 2024·2025만 넣었다**(스펙 그대로). 샤드 3~5의 NeurIPS·옛 ICLR은 쓰지 않았다. `VENUES`와 결정 매핑은 E1-L0 것이다.
5. **분야 태그**: 일반 ML은 `["general_ml"]`, AI4S는 E1-L0 slug 그대로 둔다. 별도 `ai_for_science` 태그를 붙이면 같은 논문의 레코드가 `data/processed`와 달라지기 때문이다. 여부는 `selection.jsonl`의 `ai4science`와 `is_ai4science()`로 본다.
6. **리비전 고정 URL로 받았다**(`resolve/<commit>`). 키트는 `resolve/main`으로 받았다. 같은 리비전인지는 샤드 0·1의 LFS sha256으로 확인했다.
7. **provenance 접근 시각**: 샤드 2~5에서 온 레코드는 우리가 받은 시각(2026-09-30T09:4x)이다. 키트 샤드와 papers는 키트 manifest 시각이다. 실행 시각을 쓰지 않아 출력이 결정적이다.
8. **출력 보호**: `collect_l3`는 출력 폴더 이름이 `processed_l3`가 아니면 거부한다. 실수로 `data/processed`를 덮지 않게 하려는 것이다.

## 못 한 것

- **L3 색인은 만들지 않았다**(E2 몫, 스펙 밖).
- 사전 집계 1,265(AI4S)와 1,068(같은 기준의 E1-L0 선별)의 차이는 설명하지 못한다. 사전 집계의 키워드 목록이 없다(E1-L0 검증 C1과 같다).
- 선별 오탐(약 30%)을 줄이는 키워드 정비는 E1-L0 소유라 하지 않았다. 고치면 `collect_l3_corpus.py`를 다시 돌리면 된다(키워드 sha256이 manifest에 남는다).
- 끝까지 심사평이 없는 AI4S 1편(`kqSmedTcgb`)은 코퍼스에 남겼다. E1-L0와 같은 처리이고 결정·초록은 있다. 근거 카드용으로 거르려면 `reviews_for`가 비었는지 본다.
