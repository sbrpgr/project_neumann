# [FINAL-PM] 최종 검사·교정 구현 범위

2026-10-01 대표의 병렬 개발 지시를 따른다. 기존 보강본을 연구자가 확정하면 한 작업에서 논리·물리 조건·구조를 검사하고, 근거 게이트를 통과한 수정 한 묶음을 적용한 뒤 대상 부분을 재검사하여 최종 **초안**을 반환한다. 완벽한 연구계획서나 과학적 성공을 보증하지 않는다.

## 현재 작업의 경계

- 기존 수정 권고·조립의 결과를 입력으로 사용한다. 전체 검색을 다시 돌리지 않는다.
- 의미 검사 1회, 교정 제안 1회, 교정 적용 1묶음, 도구 재검사 1회로 제한한다. 불리한 결과나 미확인 항목이 있어도 반환 후 종료한다.
- 계획서의 확정은 교정 방향의 결정이다. 목표·자료·예산·실험 성과를 임의로 바꿔 문제를 없애지 않는다. 출처·현재 문안·새 사실·수치·개인정보 게이트를 통과하지 못한 교정은 원문을 보존하고 이유를 반환한다.
- 실제 도구는 제한된 제약 검사(Z3), 단위·차원 검사(Pint), 명시된 선행 관계 검사(NetworkX)를 사용한다. 각 검사는 원문의 줄과 정확한 발췌에 연결한다. 도구가 없거나 입력이 불분명하면 미검사로 표시한다.
- 생성된 임의 Python 코드나 외부 실험 명령은 실행하지 않는다. 현재 도구 검사는 승인된 검사 종류의 계산이며, 별도의 격리 실행기가 필요한 범용 최소 실험 수행은 후속이다. 이를 실제 연구 가정 검증으로 주장하지 않는다.
- `수정 확정·검증` 한 행동과 통합 결과 화면을 제공한다. 원본과 교정 결과·미해결·도구 범위·생성 방식을 구분한다. 문안 변경 뒤 이전 결과를 현재 결과로 표시하지 않는다.
- 실제 OpenAI 호출·공개 배포·기존 서버 재시작은 이번 개발에 포함하지 않는다. mock/local 실제 도구 계산과 의미 호출 실패·미검사를 포함한 검증을 수행한다.

## 계약과 독립 검증

PM은 기존 계약을 변경하지 않고 `contracts/finalization.schema.json`과 선택 의존성 `finalization`을 추가한다. 서버 결과의 HMAC와 과학적 내용의 타당성은 구분한다. 서명 확인이 없는 기존 분석·수정 입력에는 새 최종 결과에서도 미확인 출처 표시를 유지한다.

필수 반례는 다른 문안/근거, 발췌 불일치, 지어낸 숫자·성과, 단위 오류, 모순 조건, 선행 순환, 도구 미설치, 모델 실패, 취소/시간 초과, 중복 제출, 문안 변경, 수정 거절과 재검사 상한이다. 빌더 결과 뒤 다른 모델의 독립 검증을 수행하며, 전체 검사는 단일 큐로 진행한다. 검증 완료 전 main·릴리스 완료로 표기하지 않는다.
