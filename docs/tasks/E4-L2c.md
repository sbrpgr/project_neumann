# E4-L2c — 공개 라이브 서버 안정성(대기열·속도 제한·캐시·예열·감시) (대표 지시 2026-09-30)

- 빌더: Claude Opus 5.5 · 검증: Claude Sonnet 5.5 · 목표 60분
- 소유: `src/neumann/api/serving.py`, `scripts/serve*.py`, `tests/e4/test_serving*.py`. `main.py`에는 PM이 붙인다(미들웨어·라우터·예열 함수 제공). 화면의 "대기 N번째" 표시는 `GET /queue/status`와 응답 필드로 제공하고, UI 반영 방법을 보고서에 적는다

## 배경
- 대표 승인: 프로토타입 주소 = 로컬 라이브 서버를 터널로 공개. **접근 토큰으로 막지 않는다.** 대신 심사위원·청중이 동시에 눌러도 잘 돌아야 한다(안정성 목적)
- 제약: OpenAI 속도 제한, GPU 6GB(bge-m3), 분석 1건 수십 초~수 분

## 만들 것
1. 동시 분석 상한(설정, 기본 2)과 대기열: 대기 순번·예상 대기 시간을 응답과 `GET /queue/status`로. 대기열 상한 넘으면 "잠시 후 다시" 안내(503 + 사용자 문구)
2. IP별 넉넉한 속도 제한(예: 분당 6건, 설정), 초과 시 사용자 문구
3. 입력 크기 상한(예: 50,000자), 요청 시간 상한
4. 결과 캐시: 같은 계획서(plan_id=sha256) → 캐시 즉시 응답(메모리 + 공유 `data/cache/results/`), 템플릿·데모 입력은 서버 시작 때 예열(`warmup()`: 색인·모델 로드 + 데모 결과 캐시)
5. 오류는 사용자 문구로(스택 트레이스·예외 메시지 노출 금지). 로그에 키·계획서 본문 금지(plan_id와 길이만)
6. `scripts/serve.py`: 서버 실행 + `/health` 감시, 죽으면 다시 띄움(재시작 횟수·시각 로그), 포트·호스트 설정
7. 테스트: 동시 요청 시 상한·순번, 속도 제한, 캐시 적중, 오류 문구에 내부 정보 없음, 로그에 본문 없음
## 완료 기준
위 테스트 통과, 부하 스크립트로 동시 10건을 넣어 대기열이 작동하는 로그(가짜 느린 파이프라인으로), `python scripts/verify.py` 통과
