## 순서

1. **탐색·선별(models.py 불필요):** parquet 스키마를 보고, ICLR 2024·2025 논문 중 제목·초록 키워드로 AI for Science를 고른다. 분야 3개: 소재·화학·분자 / 단백질·생물·신약 / 물리·PDE·기후. 키워드 목록은 코드 상수로 둔다. 사전 집계 기준 약 1,265편(555·671·285, 일부 겹침)과 비교해 보고한다.
2. **연결:** 심사평(공식 리뷰·메타리뷰)·저자 답변·결정을 논문에 붙인다. 결정 문자열은 확장 매핑이 필요하다(`Rejected_Submission`, `ICLR 2025 Poster` 등이 표준 매핑에서 전부 unknown이 되는 함정). 리뷰 샤드 0·1에 심사평이 없는 논문 수를 보고한다(나머지 샤드는 L3).
3. **모델 변환:** `src/neumann/models.py`(E0b가 곧 main에 넣는다)의 `Work`·`ReviewEvent`·`AuthorResponse`·`Decision`으로 바꿔 공유 데이터 폴더 `data/processed/`에 엔티티별 JSONL로 쓴다. 3단계 전에 `git log main -1 -- src/neumann/models.py`로 확인하고, 있으면 `git merge main`. 아직 없으면 1·2단계를 다듬으며 몇 분 뒤 다시 확인한다.
4. 선별·조립 결과를 `data/processed/corpus_manifest.json`에 기록한다: 편수, 분야별 수, 심사평 수, 결정 분포(거절 비율), 키워드 목록 해시, 출력 파일별 sha256, 소요 시간.
5. 조회 인터페이스: 다른 에픽이 쓸 `load_corpus(data_dir)`(Work·ReviewEvent 등을 돌려줌)를 `src/neumann/sources/corpus.py`에 둔다.

## 불변식

- 레코드마다 provenance: `source_url`은 사람이 열 수 있는 OpenReview 원문 URL(forum/note 링크), 접근 시각, 원문 해시. URL 없으면 레코드를 만들지 않는다.
- 리뷰어 신원 필드는 버린다. 리뷰 텍스트는 정규화 순서(NFC·줄바꿈 → 보일러플레이트 제거 → 신원 제거 → 저장)를 지킨다(02_data_schema §6.2).

## 완료 기준

1. `python scripts/collect_researcharcade.py`(이름은 자유) 한 번으로 조립되고, 두 번 돌리면 출력 sha256이 같다
2. 편수·분야별 수·심사평 수·거절 비율 보고(사전 집계와 비교)
3. 레코드 100%에 출처 URL, 모델 검증 오류 0, 신원 필드 0 — 테스트로 검사
4. 무작위 표본 5건: parquet 원문과 저장된 심사평 텍스트가 같은지 대조 결과를 보고서에
5. `python -m pytest tests/e1 -q`, `python scripts/verify.py` 통과. 데이터 파일은 커밋하지 않는다
