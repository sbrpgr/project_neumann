- 계획서 §3 L0(한국어 계획서 → 영어 코퍼스 문제), §4 E2(완료 기준·참고치·함정)

## 만들 것 — 인터페이스를 정확히 지킨다(E3가 이것에 맞춰 동시에 개발한다)

1. `neumann.index.sentences`: 심사평 텍스트 → 문장 목록. 문장마다 `Excerpt`(원문 오프셋, 해시, 원문 URL). `excerpt_id`는 안정적이어야 한다(같은 입력 → 같은 id)
2. `neumann.index.store`:
   - `get_excerpts(work_id) -> list[Excerpt]`: 그 논문의 심사평 문장(번호 순서)
   - `get_work(work_id) -> Work`, `get_reviews(work_id) -> list[ReviewEvent]`
3. `neumann.index.search`:
   - `search(queries: list[str], k: int = 10, exclude_work_ids: set[str] | None = None) -> list[SearchHit]`
   - `SearchHit`: `work_id`, `score`(0~1), `dense`, `lexical`, `matched_query`
   - bge-m3 임베딩(논문 제목+초록, 로컬 모델 `NEUMANN_EMBED_MODEL`, **GPU 있으면 cuda**, VRAM 6GB에 맞는 배치) + BM25(표준 라이브러리 자체 구현) 단순 결합. 한국어 질의가 들어와도 임베딩으로 찾아야 한다
   - `exclude_work_ids`는 백테스트 누출 제거용이다(E5-L2가 쓴다)
   - 점수 하한은 설정값으로 두고 기본은 낮게(0.0). 보정은 L1
4. `neumann.index.taxonomy`: **비상 경로용 최소 규칙 태거.** 문장 → R0~R9 태그 후보(키워드 사전, 영어). 다듬지 않는다. `generator="rule"`
5. `scripts/build_index.py`: 코퍼스 → 공유 데이터 폴더 `data/index/`에 문장·임베딩·BM25 색인 저장, `data/index/manifest.json`(문장 수, 태그 수, 백엔드, 빌드 시간, 입력 sha256)
6. 로드가 빠르게: 서버가 켜질 때 색인을 한 번 읽는다(모듈 단위 캐시)

## 완료 기준

1. 오프셋으로 잘라낸 원문 == 저장된 문장 텍스트: 전량 검사 100%(수치 보고)
2. 질의 3건(영어 1, 한국어 데모 계획서 1, 무관한 글 1)의 상위 10편과 점수 보고. 한국어 질의가 관련 분야를 찾는지 눈으로 확인한 결과
3. 규칙 태거 결과의 태그 종류가 2개 이상(상수 출력 금지, 옛 결함 F6)
4. 빌드 시간·GPU 사용 여부·색인 크기 보고
5. `python -m pytest tests/e2 -q`(fixture로 도는 테스트), `python scripts/verify.py` 통과. 색인 파일은 커밋하지 않는다
