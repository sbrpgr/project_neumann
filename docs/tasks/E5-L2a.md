## 만들 것 — 평가 결과를 보기 전에 규칙을 코드와 커밋으로 고정한다

1. **표본(`eval/backtest_sample.py`):** AI for Science 코퍼스에서 30편, 거절·채택 비율을 모집단과 같게 층화, 시드 고정(`random.Random(20260930)`). 목록과 sha256을 `data/eval/backtest_sample.json`에. 앞에서부터 15편이 축소 표본이 되게 순서를 고정
2. **계획서 만들기(`eval/backtest_plans.py`):** 초록에서 수치·우월성·실증 문장을 **통째로 드롭**(마스킹 아님). 정규식 3종(NUM·CLAIM·EVID). 잔여 패턴 0 자동 검사, 400자 미만이 된 계획서 수 보고(수동 복구 대상 표시만)
3. **누출 제거:** 대상 논문과 그 심사평을 검색에서 뺄 `exclude_work_ids` 목록. **접두어·네임스페이스를 정규화한 뒤** 제목 정규화 일치 ∪ 심사평 해시 일치로 제외. 자기 논문 id를 주입해 검색 결과 0건이 나오는지 회귀 테스트(옛 함정 B-10). 검색 함수는 `neumann.index.search.search(..., exclude_work_ids=...)`(E2)
4. **셔플 대조 짝:** 같은 분야 다른 논문과 시드 고정 무작위 짝
5. **일반 LLM 기준선(`eval/baseline_llm.py`):** 같은 OpenAI 모델(`gpt-6-astra`)에 계획서만 넣고 "이 연구계획서가 심사에서 받을 위험 3개를 구체적으로". 위험 정확히 3개, 하나에 2문장 이내. **프롬프트 원문을 파일로 공개**(`eval/prompts/baseline_llm.txt`). 결과 캐시
6. **판정 봉투(`eval/judge_envelope.py`):** 판정자 입력 = 계획서, 위험 3개(두 시스템 섞어 무작위 순서, 시스템명·근거 인용·원문 링크·카드 번호 제거), 그 논문의 실제 심사평 전문. 출력 = 위험마다 A/B/C + 한 줄 이유. **모델과 무관한 파일 형식**(JSON)으로 정의. 봉투 id에서 시스템을 알 수 없게. 비밀 짝 표(어느 위험이 어느 시스템인지)는 별도 파일
7. **판정 실행기(`eval/judge_run.py`) — 두 경로 모두:** 
   - Claude 경로: 봉투 파일 목록을 받아 Claude Code 서브에이전트가 읽고 답 파일을 쓰게 하는 **지시문 생성**(PM이 서브에이전트를 띄운다). 판정자 3명 격리
   - Codex 비상 경로: 같은 봉투를 `codex exec -m gpt-6-sol`로 돌리는 명령 생성·실행 함수(§5.6·§5.7). 실제 실행은 PM 지시가 있을 때만
   - 답 파일 검증(형식·누락), 위험별 다수결(3명 모두 다르면 B), 짝 표로 시스템 복원
8. **지표(`eval/backtest_metrics.py`):** 적중률(precision@3), Top-3 적중(hit@3), 오탐률, 특이성(진짜 − 셔플), 근거율, 모두 n과 95% 부트스트랩(2,000회, 시드 고정), Neumann − 일반 LLM은 짝지은 부트스트랩. 대표 블라인드 판정 10편과의 일치율·κ 계산 함수

## 완료 기준

1. 표본 30편 목록·sha256·층화 분포 보고. 계획서 30건 생성, 잔여 패턴 0
2. 누출 회귀 테스트: 자기 논문 주입 → 0건(E2 검색이 main에 없으면 fixture 검색으로 테스트하고 보고서에 적기)
3. mock 판정 답으로 봉투 → 다수결 → 지표 전 과정이 도는 테스트, 블라인드(봉투에 시스템 흔적 없음) 테스트
4. 일반 LLM 기준선을 실제 astra로 3편 돌린 결과(위험 3개 형식 준수)
5. `python scripts/verify.py` 통과. 표본·계획서·판정 데이터는 공유 데이터 폴더에만(커밋 금지), 프롬프트 원문은 커밋
