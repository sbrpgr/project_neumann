## 만들 것

1. `src/neumann/llm.py`: provider `openai`(Responses API, `gpt-6-astra`)·`mock`. 모든 호출은 **JSON 스키마 요청 → 로컬 재검증** 한 경로. 호출마다 시간 상한(설정), 추론 강도(설정 키, 호출별), 실패·초과 시 예외 대신 "실패" 결과를 돌려 호출부가 비상 경로로 가게. `temperature` 보내지 않음. 키는 설정에서만(SecretStr). 로그에 요청 헤더·키 금지. mock provider는 fixture에 맞는 결정적 응답
2. `src/neumann/analyze/` 3단계(계획서 §3 L0)
   - 계획서 정규화: 줄 번호, `PlanDocument`, 개인정보(이메일 등) 마스킹 최소판
   - **astra ① 검색어·축:** 계획서 → 영어 검색어 3~6개 + 방법·데이터·평가 축(호출 1회). 실패 시 계획서의 영문 기술어로 대신
   - 검색: `search()`로 유사 연구 약 10편
   - **astra ② 지적 추출(EX-4 계약):** 논문마다 심사평 문장(Excerpt) 묶음 → 발췌마다 0개 이상 지적: `excerpt_id`(입력 id enum), `start`·`end`(발췌 안 위치, 선택: 없으면 문장 전체), `risk_code`(R0~R9 enum), `polarity`, `confidence`. **인용문 필드 없음.** 코드가 원문을 잘라 인용을 만들고 범위 밖·빈 구간·enum 밖은 버린다(폐기 수 기록). 논문 단위 병렬 호출, 결과를 심사평 해시로 공유 데이터 폴더 `data/cache/`에 캐시
   - **astra ③ 카드 합성:** 추출된 지적 → 위험카드. 모델은 카드 제목, 이 계획서에 해당하는 이유(계획서 **줄 번호**), 근거 excerpt_id 목록만 돌려준다. 코드가 id 존재를 검증하고 인용·원문 링크를 붙인다. 점수(유사도 × 빈도 × 심각도 × 신뢰도)는 코드가 계산
   - 카드 조립 불변식: 카드당 근거 3건 이상·논문 2편 이상, 카드 최대 8장, R0는 카드로 만들지 않음. **카드 0장이면 이유를 결과에 담는다**
   - **비상 규칙 경로:** 단계별로 API 실패·시간 초과면 그 단계만 규칙(태그 빈도 카드)으로 대신하고 `StageStatus`에 degraded로 기록. 카드마다 `generator` 정직 표기
3. `src/neumann/pipeline.py`: `run_premortem(plan_text: str, *, session_id: str | None = None) -> PremortemResult`. 단계별 소요 시간 기록. 예외로 죽지 않고 강등을 기록
4. 무관한 입력(조리법 등): 카드 0장과 사유(검색 점수·astra 판단 중 근거를 결과에)

## 완료 기준 (계획서 §3 L0와 같다)

1. mock provider로 `tests/e3` 통과: 인용 오프셋 대조, 범위 밖 지적 폐기, 근거 없는 카드 거부, 비상 경로 강등 기록, 카드 0장 사유
