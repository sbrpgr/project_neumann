# E4-L0 — API 골격과 화면(목업 기반)

- 빌더: Claude Opus 5.5 · 검증: Claude Sonnet 5.5
- 목표 시간: 70분
- 소유: `src/neumann/api/`, `src/neumann/webui/`, `tests/e4/`

## 읽을 것

- 계획서 §4 E4(화면 데이터 계약, L0 범위, 함정)
- `05_디자인_규칙.md` 전부
- 목업 `부록/목업/web/index.html`(최신, `<script id="DATA">`가 화면 데이터 계약), 참고로 `Input.dc.html`·`Main.dc.html`·`Evidence.dc.html`
- `contracts/ui_view.schema.json`

## 만들 것

1. `src/neumann/api/main.py` (FastAPI)
   - `GET /` → `webui/index.html`
   - `GET /health` → `{"status":"ok","version":...,"stages":{...}}`: 단계별 구현 가용성(모듈 import 가능 여부)을 정직하게
   - `POST /premortem` (계획서 텍스트) → 분석 결과 JSON
   - `POST /premortem/view` (계획서 텍스트) → `ui_view` 계약 JSON
   - 분석은 E3가 만드는 `neumann.pipeline.run_premortem`을 **지연 import**한다. 아직 없으면 fixture로 만든 샘플 뷰를 돌려주고, 응답과 화면에 "분석 파이프라인 미연결(샘플 데이터)"을 표시한다. 조용히 가짜를 내지 않는다
2. `src/neumann/api/view.py`: 분석 결과 → `ui_view` 계약 dict(`build_ui_view`). 예외를 던지지 않고, 빠진 부분은 빈 값과 상태로 채운다. 계약 검증은 `jsonschema`로
3. `src/neumann/webui/index.html`: 목업 `web/index.html`을 기반으로 한다. 하드코딩된 DATA 대신 `/premortem/view` 응답을 렌더한다. L0 화면: 입력(붙여넣기) → 리포트(요약·유사 연구 목록·위험카드, 카드마다 인용과 원문 링크). 목업의 다른 화면 요소는 데이터가 없으면 숨기거나 "준비 중"으로
4. 폰트: `공개자료/fonts/` 5종을 `webui/fonts/`로 복사(각 폴더의 OFL.txt·LICENSE 포함)하고 로컬로 서빙한다. **CDN 금지**. 목업 헤더의 대표 실명 배지는 그대로 둔다(대표 결정)
5. 실행: `python -m uvicorn neumann.api.main:app --host 127.0.0.1 --port 8000`

## 완료 기준

1. `python -m pytest tests/e4 -q`: `/health` 200, `/premortem/view` 응답이 `ui_view.schema.json` 통과, 파이프라인 미연결일 때 상태 표시가 응답에 있음
2. 서버를 띄우고 Playwright(1440×900)로 입력 → 리포트를 찍는다. 렌더 완료 DOM 조건을 기다린 뒤 찍는다. `docs/reports/E4-L0_input.png`, `docs/reports/E4-L0_report.png`
3. 콘솔 오류 0, 외부 도메인 요청 0(Playwright 네트워크 기록으로 확인해 보고서에)
4. `python scripts/verify.py` 통과
