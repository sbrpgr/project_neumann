# 시연 시나리오 — 07:30 녹화용 (3~4분)

- 목적: "처음부터 끝까지 동작하는 에이전트"를 한 번에 보여 준다. 흐름이 영상의 뼈대다.
  - 불완전한 계획서 → 근거 달린 분석 → 수정 권고(재탄생) → 연구자 확정 → 최종 점검·수정(도구 검증) → 완성도를 높인 초안 → 내보내기
- 정의(대표 원문, 글자 그대로): "Neumann의 에이전트는 불완전한 연구계획을, 불완전한 거절 기록들을 모아 설명해 주고, 완전한 기획으로 다시 재탄생시켜 주는 에이전트."
- 근거 문서: `docs/decisions.md`의 10/01 02:5x(최종 제품 형태), 03:1x(방향 전환), 03:3x(07:00 완성 기준), 00:2x(시연 샘플 선별), 23:1x(입력 300자·정의).
- 작성: E6-pres5, 10/01 03시 기준. 07:00 동결 때 §1 표를 다시 채운다.

## 0. 지킬 것

1. **시연 예시(선별).** 샘플은 좋은 결과를 골라 둔 것이다. 화면 자막에 "시연 예시(선별)"를 늘 띄운다. 성능은 말하지 않는다. 성능 주장은 발표 12쪽 백테스트(n=5, 통계적 결론 없음)로만 한다.
2. **목업은 목업이라고 쓴다.** 목업 화면이 들어가는 샷은 화면 왼쪽 위에 "목업 · 가짜 데이터 · 서버 호출 없음"을 고정 자막으로 둔다. 목업의 숫자와 도구 결과를 실제 결과처럼 읽지 않는다.
3. **도구 검증과 연구자 코드 실행을 섞지 않는다.**
   - 이번 버전의 최종 점검은 계획서 문장에 적힌 수치·단위·구조를 오프라인 라이브러리로 계산한다. 논리·수치 제약은 Z3, 단위는 Pint, 구조(선행 관계 순환)는 NetworkX, 합계는 산술 일관성이다. 점검 유형에 따라 코드가 도구를 고른다(LLM이 고르지 않음).
   - 연구자의 코드를 실행해 보는 기능은 이번 버전에 없다. 로드맵(발표 15쪽 STAGE 1)에만 있다. 영상과 말에서 "실행해 봤다"는 인상을 주지 않는다.
   - **주의:** 8172 최종 형태 목업(FIN-UI)의 가짜 도구 기록에 `sandbox` "제한 실행(계산만)" 줄이 있다(`n = 12000; ratios = …` 실행). 이 줄은 코드 실행으로 읽힌다. 녹화 전에 FIN-UI가 목업 데이터에서 빼야 한다. 빼지 못하면 그 줄이 보이지 않게 자르고, 논리 점검 설명의 "제한 실행"도 화면에 남기지 않는다.
4. **최종 점검은 한 번이다.** 연구자가 확정한 뒤 한 번 돌고, 찾은 오류는 그 자리에서 고친다. 다시 도는 루프는 없다. 연구자만 아는 사실은 지어내지 않고 `[확인 필요]`로 남긴다.
5. **모델 표기.** 화면·자막은 "LLM (gpt-6.1-sol)"로 쓴다. 화면에 "astra" 글자가 보이면 그 샷을 쓰지 않는다.
6. **API 호출.** 라이브 실행은 시연 샘플 2~3편의 전체 흐름을 각 1회만 한다(decisions 03:1x, 편당 약 $1, 대표 승인 범위). 8020을 main 최신으로 재기동한 뒤 06:00~06:30에 한다. 녹화 리허설은 mock 서버나 목업으로 한다.
7. **공개 주소.** 터널은 필수 보안 관문(SEC-8 필수 항목, PUB-A·B·C)을 통과했을 때만 연다. 통과 전에는 영상 끝의 주소를 【공개 후 기입】으로 둔다.
8. **대기 시간.** 편집으로 줄인 곳에는 "실제 N초 → 편집" 자막을 단다.

## 6. 예상 질문 추가분 — 최종 형태와 도구

기존 질의응답 작업본(`data/deck/질의응답_작업본.docx`)에 없는 질문이다. 답은 07:00 병합 상태에 맞춰 【병합 후 확정】을 떼거나 남긴다.

**F1. 최종 점검은 정확히 무엇을 하나요?**
- 답: 연구자가 확정한 문안을 고정하고 한 번 점검합니다. 의미 검사 1회로 논리·물리·구조 문제와 도구로 확인할 항목을 뽑습니다. 코드가 도구로 계산하고, 교정 제안 1회에서 원문 줄에 맞는 수정만 최대 8줄 한 묶음으로 적용합니다. 고친 줄에 걸린 검사만 한 번 다시 돌립니다. 반복 루프는 없습니다. 【병합 후 확정】
- 근거: Codex 후보 `FINAL-ENGINE`·`FINAL-PM` 보고(codex/finalization-20261001), decisions 02:5x.

**F2. "도구로 검증한다"는 게 LLM이 도구를 고른다는 뜻인가요?**
- 답: 아닙니다. 점검 유형별로 코드가 도구를 정합니다. 논리·수치 제약은 Z3, 단위는 Pint, 선행 관계 같은 구조는 NetworkX, 합계는 산술 일관성 검사입니다. LLM은 어느 줄의 어떤 표현을 볼지만 제안하고, 수치·단위·합계 판정은 도구 결과로만 합니다. 모두 오프라인입니다.
- 하지 말 것: "에이전트가 알아서 도구를 골라 실험한다."

**F3. 연구자의 코드를 실행해 검증하나요?**
- 답: 이번 버전에는 없습니다. 도구 검증은 계획서에 적힌 숫자·단위·관계를 계산하는 것이지, 연구 코드나 실험을 돌리는 것이 아닙니다. 구현 경로 제시와 승인·격리된 최소 실행 검증은 다음 단계(15쪽 STAGE 1)입니다.

**F4. 물리적 오류를 어떻게 잡나요?**
- 답: 계획서에 단위와 함께 적힌 값의 차원과 변환을 Pint로 확인합니다. 잡을 수 있는 유형은 단위 오기(상온을 25 K로 적는 식)나 서로 더할 수 없는 단위의 합 같은 것입니다. 물리 법칙 전반의 타당성을 판정하지는 않습니다.

**F5. 논리 오류는요?**
- 답: 적힌 합계·곱·비교 제약은 Z3로, 선행 관계의 순환은 NetworkX로 확인합니다. 그 밖의 논리 문제는 의미 검사가 표시하되, 도구로 확인되지 않으면 "미확인"으로 남기고 통과로 치지 않습니다.

**F6. LLM이 수치를 잘못 뽑으면 도구도 틀리지 않나요?**
- 답: 도구 입력의 숫자는 원문 줄 인용과 정확히 일치해야 하고 그 줄에 한 번만 나와야 합니다. "약", "아닌", 조건이 붙은 수치나 모호한 표현은 검사하지 않고 "미확인"으로 둡니다.
- 근거: `FINAL-TOOLS` 보고, 독립 검증 `FINAL-INDEPENDENT`(부정 수치 반례를 고침).

**F7. 그 자리에서 고친다는데, LLM이 새 사실을 지어내면요?**
- 답: 교정은 원문 앵커가 맞는 줄만 바꿉니다. 새 숫자, 기관명, 개인정보, 마크업, 새 과학 내용이 들어간 수정은 게이트가 거절하고, 거절된 문장은 결과에 싣지 않습니다. 연구자만 아는 값은 `[확인 필요]`로 남깁니다.

**F8. 왜 반복하지 않고 한 번만 점검하나요?**
- 답: 대표 결정입니다. 한 번 점검·수정하고 결과를 돌려주면, 무엇이 바뀌었는지 사람이 따라갈 수 있습니다. 시간과 비용에도 상한이 생깁니다. 더 고칠지는 연구자가 새로 요청합니다.

**F9. 최종 점검을 통과하면 계획서가 맞다는 뜻인가요?**
- 답: 아닙니다. "완료"는 정해진 점검이 끝났다는 뜻이지 오류가 없다는 보장이 아닙니다. 과학적 타당성이나 선정 여부도 보장하지 않습니다. 화면에도 그렇게 씁니다.

**F10. 최종 점검이 반려율을 줄이나요? 성능은요?**
- 답: 재지 않았습니다. 반려 가능성을 줄이는 것은 목표이고, 측정한 효과가 아닙니다. 성능은 분석 단계 백테스트(n=5, 통계적 결론 없음)만 있습니다. 보강 전후 쌍비교는 다음 과제입니다.

**F11. 최종 점검은 실제 모델로 확인했나요?**
- 답: 후보 브랜치에서는 mock으로만 확인했습니다. 집중 검사 68건, 브라우저 1건, 전체 검사 2,175건이 통과했습니다. 실제 모델(gpt-6.1-sol) 확인은 시연 샘플 2~3편 전체 흐름으로 합니다. 【측정 중】

**F12. 영상에 나온 샘플은 골라낸 것 아닌가요?**
- 답: 맞습니다. 그래서 "시연 예시(선별)"로 표시했고, 샘플로 성능을 말하지 않습니다. 성능 주장은 사전 등록한 백테스트로만 합니다.

**F13. 영상의 도구 결과가 목업인가요?**
- 답: 목업 장면은 화면에 "목업 · 가짜 데이터"라고 적었습니다. 목업의 도구 기록은 실제 Z3·Pint·NetworkX 실행 결과가 아닙니다. 실제 결과는 병합본 장면에만 있습니다.

**F14. 분석은 얼마나 걸리나요?**
- 답: 서버를 막 띄운 첫 분석은 모델을 올리느라 166초가 걸렸고, 그래서 녹화 전에 예열합니다. v1 라이브(gpt-6.1-sol)에서 예시 3건은 화면 전체 85~155초였습니다. 수정 권고와 최종 점검 시간은 【측정 중】입니다.

**F15. 비용은요?**
- 답: 분석 1건의 LLM 비용은 약 200원 이하로 추정합니다. 수정 권고부터 최종 점검까지 포함한 전체 흐름은 편당 약 1달러로 추정했고, 실측은 【측정 중】입니다.
- 근거: 14쪽 추정, decisions 03:1x "편당 약 $1".

**F16. 데이터를 더 모으면 더 좋아지나요?**
